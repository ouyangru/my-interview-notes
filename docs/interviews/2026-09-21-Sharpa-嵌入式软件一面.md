### 问题 2 · TBox 是什么、硬件形态是什么、ARM 还是 x86

- 结论：基本正确
- 状态：`[learning] [interview] [project]`
- 影响程度：中

- 遗漏：没有先明确“我不负责 BSP/Modem/CAN 驱动”，也没有把云端通道、板内通信和执行结果回传串完整。

### 问题 4 · Linux 收到的是业务指令，还是底层执行器参数

#### 1. 面试官原问题

**面试官：**

> 比如要控制方向、控制转速，需要多个轮配合。它是直接给你说控制哪个东西到什么位置，还是你需要在里面做计算或者解析？

#### 2. 我当时的回答（全文）

**我：**

> 这边是会有一个解析。它会存在一个配置的映射表。如果从云端下发一个，比如我要开空调，或者说打开车门上的锁，那么 Linux 的应用会有一个映射表，把从云端下发的指令映射成一些字段，然后再通过协议发送到 MCU。

#### 3. 复盘判断

- 结论：基本正确
- 状态：`[learning] [interview] [project]`
- 影响程度：中
- 问题：没有明确说明 TBox 并不做车辆运动控制算法，容易让“业务解析”和“运动学/执行器控制”混在一起。

#### 4. 推荐回答（完整版本）

> 在我实际接触的 TBox 远控场景里，Linux 侧不负责轮速分配、转向控制这类运动控制算法。云端下发的是业务语义，例如开空调、解锁等，Linux 应用负责按照协议把 command id 和参数映射成与 MCU 约定的数据结构，再发送给 MCU。真正具体到 CAN Signal、某个 ECU 的执行动作和实时控制，是 MCU 和目标 ECU 一侧完成的。
>
> 所以这里所谓“解析”主要是协议解析和业务映射，而不是运动控制计算。

### 问题 6 · TBox 项目难点是什么

#### 1. 面试官原问题

**面试官：**

> 你觉得这个项目难点是什么？你觉得它复杂的地方是什么？

#### 2. 我当时的回答（全文）

**我：**

> 我觉得这个难点可能是在于，比如我接收到云端下发一些指令的时候，需要对它进行正确解析。然后还会存在一些，比如这个指令执行不成功以后要重试，或者上报一些错误，在这一方面需要做具体措施。
>
> 然后它的一些控制指令可能会有很多不一样的控制指令，在这个过程中可能会存在一些状态的处理，我觉得难点是在于这个。

#### 3. 复盘判断

- 结论：答得过于泛化
- 状态：`[weak] [interview] [project]`
- 影响程度：高
- 问题：没有拿真实工程问题作证，只说“解析、重试、错误处理”，这类话任何项目都可以套。
- 更好的真实故事：TCP partial send / EAGAIN / ACK 超时、voice core 崩溃、DTC 上报条件、TBench 日志竞态等。

#### 4. 推荐回答（完整版本）

> 我觉得真正难的不是协议字段本身，而是通信链路不稳定时如何保证状态机正确。例如 TCP 连接可能断开，send 可能只发送一部分或者返回 EAGAIN，业务 ACK 也可能超时，所以不能把“send 调用成功”直接等价成“业务成功”。
>
> 我在 MSD 上报里会把连接状态、发送状态和业务 ACK 分开处理：连接断开时重建连接；数据没有发完时保存 buffer 和 offset，等 socket 再次可写以后继续发送；消息已经发出但 ACK 超时，则由业务层决定重试或上报失败。这个过程里最重要的是把网络层成功和业务执行成功区分开。

### 问题 7 · CAN 总线上控制报文和状态报文如何“抢占”

#### 1. 面试官原问题

**面试官：**

> CAN 线上一直在跑上传数据，比如温度、状态信息。如果现在往底下发一个控制指令，它和这些数据之间有一个抢占问题，你怎么解决？

#### 2. 我当时的回答（全文）

**我：**

> 这一块的话，我理解可能会存在一个队列。如果说我想要发送这样一个指令，然后就把需要执行发送的事件给它放到事件队列里面，然后一个一个进行串行处理。
>
> 就我对 TBox 的了解，它可能对实时性这一块要求并不是特别高，所以如果控制指令下发经过一段时间，其实是可以接受的。

#### 3. 现场继续追问与我的回答

**面试官追问：**

> 那你的车身安全信息呢？如果是一些异常的上报呢？

**我当时的回答：**

> 关于一些异常的上报，这一块我还真没有考虑得这么多。

#### 4. 复盘判断

- 结论：答错核心考点
- 状态：`[weak] [wrong] [interview]`
- 影响程度：高
- 错误点：面试官问的是 CAN 总线多节点/多报文竞争，现场回答成了应用层事件队列。
- 修正：CAN 使用基于 Identifier 的逐位无损仲裁，数值更小的 ID 通常优先级更高；应用层队列是另一个层级的问题。
- 这是重复薄弱点：2026-09-10 恒玄一面已经暴露过 CAN 基础不稳，本次再次出现。

#### 5. 推荐回答（完整版本）

> 这里需要分两层看。Linux 应用层确实可能用队列管理待发送业务消息，但真正多个节点同时竞争 CAN 总线时，是 CAN 协议本身做仲裁。
>
> CAN 在仲裁字段逐位比较，显性位 0 会覆盖隐性位 1，所以报文 ID 数值更小的一方会继续发送，其他节点停止发送并等待下一次总线空闲。这个过程是无损仲裁，获胜报文本身不需要重发。
>
> 因此安全性或者实时性更高的报文，在系统设计阶段通常会分配更高的 CAN 优先级。对我参与的 TBox 链路来说，Linux 侧只是把请求发给 MCU，真正 CAN 发送和总线仲裁发生在 MCU/CAN 控制器及总线这一侧。

>

>
> 所以我把生产和消费解耦：采集线程只负责持续产生最新 Frame，StreamManager 做 fan-out，每个客户端维护独立发送队列，用 epoll/EPOLLOUT 驱动非阻塞发送。队列不能无限长，因为那样延迟会持续增加，所以实时预览场景下我更愿意丢旧帧而不是完整保存历史帧。
>
> 如果现在重新做延迟评估，我会在采集出队、协议封装、入客户端队列、socket 发送、客户端接收和渲染几个节点打 monotonic timestamp，再按同一个 frame id 算每段耗时。

> 我首先会确定花屏从哪一层开始出现，而不是直接认定是网络。第一步是在 V4L2/编码输出后把 H.264 直接 dump 到本地文件，不经过网络，用播放器验证。如果本地文件已经花屏，问题就在 Sensor、采集或者编码这一侧。
>
> 如果本地 H.264 正常，再检查协议封装，例如 H.264 的 NALU 边界、SPS/PPS 和 IDR；HTTP-FLV 还要检查 AVC sequence header、Tag 长度以及 Annex-B 到 AVCC 的转换。
>
> 如果服务器侧封装后的流本地播放也正常，再看网络发送。TCP 本身会保证可靠有序，所以重点不是笼统说“TCP 丢包”，而是检查应用程序有没有 partial send 没处理完整、EAGAIN 后没有续发、buffer 提前释放，或者客户端重连以后从非关键帧开始。RTSP/RTP 如果走 UDP，则可以抓包看 RTP sequence number 是否跳号。
>
> 最后还可以换 VLC、GStreamer 等客户端交叉验证。通过每个阶段保存一个可独立播放或可验证的数据，就能找到第一次出现错误的节点。

### 问题 18 · 系统从上电到启动完成的完整流程

#### 1. 面试官原问题

**面试官：**

> 结合一个具体案例，系统从上电的一刻起，一直到启动完成，这个引导流程是怎么样的？

#### 2. 我当时的回答（全文）

**我：**

> 系统上电的话，首先会启动固化在 ROM 里面的一段 BIOS 软件，这段软件主要会进行硬件自检，然后再把启动盘中的第一个扇区程序加载到内存中执行。
>
> 执行这一小段扇区程序的时候，因为它本身并不是整个 Bootloader，所以后续还会把 Loader 程序加载进内存继续运行。
>
> Loader 一开始运行在 16 位实模式，在这边会先进行内存检查，然后初始化对应的 GDT 表，再进行从 16 位实模式到 32 位保护模式的切换。
>
> 切换到保护模式之后，就会加载启动内核所需要的一些资源，之后再跳转到内核执行。
>
> 内核执行的时候会初始化内存管理、文件系统和进程调度，然后再启动第一个应用程序。大体流程应该就是这样。

#### 3. 复盘判断

- 结论：本场相对较好的回答
- 状态：`[learning] [interview] [project]`
- 影响程度：低/中
- 主干：BIOS → MBR → Loader → 实模式 → GDT → 保护模式 → Kernel → 子系统初始化 → 用户程序，基本成立。
- 可加强：如果讲的是自己教学 OS，明确“传统 BIOS/MBR”；不要和后面的产品级 A/B slot 机制混为一谈。

#### 4. 推荐回答（完整版本）

> 如果先讲我的 x86 教学 OS，它采用传统 BIOS 启动。CPU 复位后从固定地址执行 BIOS，BIOS 完成基本硬件初始化后读取启动盘 MBR 的 512 字节到内存并跳转。MBR 空间有限，所以只负责加载后续 Loader。
>
> Loader 获取内存信息、准备 GDT，设置 CR0.PE 进入保护模式，再建立必要的分页结构，从磁盘把 kernel ELF 加载到内存并跳到内核入口。
>
> 内核启动以后继续初始化中断、物理和虚拟内存、任务管理、文件系统等子系统，最后创建第一个用户进程并进入 shell。

### 问题 19 · A/B 分区到底由谁决定启动哪个 Slot

#### 1. 面试官原问题

**面试官：**

> 我刚刚说了 A/B 分区。它有两个分区，是从哪里开始决定从哪个分区启动？
>
> 里面会记录什么信息？

#### 2. 我当时的回答（全文）

**我：**

> 这里的话我还真有点不知道。不过我记得内核里面似乎有一个环境变量来存储当前是 A 分区还是 B 分区。
>
> 如果有决定的话，应该会记录……这块我还真不太清楚。

#### 3. 复盘判断

- 结论：答错/不会
- 状态：`[weak] [wrong] [interview]`
- 影响程度：高
- 错误点：把 slot selection 放到了“内核里的环境变量”。真正决定从哪一个 slot 加载 kernel/rootfs 的动作通常发生在 Bootloader 阶段，因为目标内核此时还没启动。

#### 4. 推荐回答（完整版本）

> Slot 选择发生在 Bootloader 阶段，而不是目标内核起来以后。系统会在持久化区域保存 A/B 的 slot metadata，Bootloader 上电后读取这些信息，比如当前 slot 的 priority、是否已经成功启动、剩余尝试次数等，然后选择一个可启动 slot，并加载对应的 kernel/rootfs。
>
> OTA 一般写 inactive slot，写完以后把它设置成下一次优先启动的 slot。新系统第一次启动成功以后再确认 successful boot；如果连续启动失败，Bootloader 可以把尝试次数减到 0，再回退到旧 slot。
>
> 不同平台具体 metadata 格式会不同，但“Bootloader 选 slot，再加载对应内核”这个阶段关系是固定要先说清楚的。

### 问题 20 · I²C 总线上挂多个从设备，如何和其中一个通信

#### 1. 面试官原问题

**面试官：**

> 比如一个 I²C 总线上底下挂了三个从设备，然后我想跟其中一个设备通信，它的时序是什么？

#### 2. 我当时的回答（全文）

**我：**

> 这边我记得是会……拉高电平，然后再发送我想要通信的这个从机的一个……[后续回答混乱，未能形成完整 START / address / ACK / data / STOP 流程]。

#### 3. 复盘判断

- 结论：不会
- 状态：`[weak] [interview]`
- 影响程度：高
- 重复薄弱点：2026-09-10 恒玄科技一面已经直接不会 I²C START/STOP，本次再次答不出来，明确属于重复薄弱点，不是单次紧张。
- 核心混淆：I²C 通过地址选择从设备，不像 SPI 用独立 CS 线。

#### 4. 推荐回答（完整版本）

> I²C 只有 SCL 和 SDA 两根信号线，两根都是开漏结构并通过上拉电阻保持空闲高电平。主机开始通信时，在 SCL 保持高电平时把 SDA 从高拉低，形成 START。
>
> 然后主机发送 7 位从机地址再加 1 位读写位。所有从机都能看到地址，但只有地址匹配的设备在第 9 个时钟周期拉低 SDA 返回 ACK。之后按字节传输数据，每个字节后面都有 ACK/NACK。通信结束时，在 SCL 为高时让 SDA 从低变高形成 STOP。
>
> 所以一条总线上挂多个设备时，真正选择设备的是地址，而不是额外片选线。

> [该句录音 ASR 不完整，无法确认完整原话。]

#### 4. 复盘判断

- 结论：答错
- 状态：`[weak] [wrong] [interview]`
- 影响程度：高
- 核心错误不是 KMP 不会，而是题意理解错：
  - 子串 substring：要求连续；
  - 子序列 subsequence：只要求相对顺序。
- 这份代码实际上更接近“尝试判断 A 是否是 B 的子序列”，且方向与题目相反。
- 还有额外实现问题：
  - `length_A < length_B` 后输出 `-1` 但没有 `return`；
  - 最终判断用 `index_A == length_A`，进一步证明匹配目标写反；
  - 现场基础题花费较长时间，说明题意确认和代码前 sanity check 需要加强。

#### 5. 推荐回答（完整版本）

> 这题如果不要求 KMP，先用朴素匹配就够了。我会枚举 B 在 A 中可能开始的位置 i，然后连续比较 A[i+j] 和 B[j]。只要某个起点能把 B 全部连续匹配完，就返回 true。
>
> 朴素做法最坏 O(nm)，如果面试官继续要求线性复杂度，再补 KMP 到 O(n+m)。

```cpp
bool isSubstring(const string& a, const string& b) {
    if (b.empty()) return true;
    if (b.size() > a.size()) return false;

    for (int i = 0; i + b.size() <= a.size(); ++i) {
        int j = 0;
        while (j < b.size() && a[i + j] == b[j]) {
            ++j;
        }
        if (j == b.size()) return true;
    }
    return false;
}
```

#### 6. 易错点

- `substring` = 子串 = 连续。
- `subsequence` = 子序列 = 不要求连续，只要求顺序。
- 代码前先口述 2 个例子：
  - `"abcdef", "bcd"`：子串成立；
  - `"abcdef", "ace"`：子序列成立，但不是子串。
