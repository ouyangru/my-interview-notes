### 问题 4 · socket 通信有哪些函数 / 客户端如何建连

#### 1. 面试官原问题

**面试官：** 你说做过 socket 通信，那建立连接和收发数据一般会用到哪些函数？

#### 2. 我当时的回答（全文）

**我：**

> 您说的是这个 socket 的通信吗？首先就是它在建立连接的过程中，我这个客户端这边首先会绑定这个远程服务端的 IP 和端口号，就是用 bind 函数。然后后面就可以使用 connect，就相当于在建立两个机器的一个 TCP 连接。然后我通过 connect，它就会获取到一个 fd，然后我的 listen 在监听这个 fd，也就是监听这个 fd 的数据。然后还有一个 recv 函数，就是可以相当于把我接收到的数据给它接收到一个指定的内存地址。还有 send 就是相当于发送我这个 TCP 的一些数据。我了解到一些 socket 通信的一些函数，就是这样。

#### 3. 现场继续追问与我的回答

**面试官追问：** `listen` 是在什么时候调用的？和三次握手是什么关系？

**我当时的回答：**

> 我记得好像是在建立三次握手的时候吧。然后 listen 函数，它这里是相当于我已经建立完，就是已经有这个 TCP 链路了，然后我再相当于监听这个文件描述符。

#### 4. 复盘判断

- 结论：答错。
- 状态：`[weak] [wrong] [interview]`
- 影响程度：高

#### 5. 当时回答的问题在哪里

- 错误原话：`客户端这边首先会绑定远程服务端的 IP 和端口号，就是用 bind 函数`。
- 问题：常规客户端主流程不是绑定远程地址，而是 `socket -> connect`；服务端才 `bind -> listen -> accept`。
- 错误原话：`connect 它就会获取到一个 fd`。
- 问题：fd 是 `socket()` 返回的，不是 `connect()` 返回的。
- 错误原话：`listen 在监听这个 fd 的数据`。
- 问题：`listen` 不是监听数据，而是让服务端 socket 进入监听连接请求状态。

#### 6. 推荐回答

> socket 通信要先区分客户端和服务端。服务端通常是 `socket -> bind -> listen -> accept -> recv/send`，其中 `bind` 是绑定本地 IP 和端口，`listen` 是让 socket 进入监听状态，`accept` 才是真正接受客户端连接并返回已连接 socket。客户端通常是 `socket -> connect -> recv/send`，`connect` 是在已有 socket fd 上主动向服务端发起连接。连接建立以后，双方才通过 `send` 和 `recv` 进行数据收发。实际项目里公司会把这些系统调用封装成通信框架或事件循环接口，但底层流程本质上还是这个。

### 问题 6 · select / poll / epoll 区别

#### 1. 面试官原问题

**面试官：** select、poll、epoll 有什么区别？

#### 2. 我当时的回答（全文）

**我：**

> 其实这三个都是一个多路复用的方式。因为 select 它是会遍历这个文件描述符，然后如果我的客户端连接数量很多的话，它的时间复杂度是 O(n)，性能会比较差。而 epoll 的话，它是基于红黑树和链表，它首先会把一些要监听的事件先放入红黑树。等到这些其中的一些事件就绪以后，才会把这些就绪的事件放入就绪列表。之后我的 epoll 只用遍历这个就绪列表，就可以执行这些事件。所以 epoll 相比 select 和 poll，首先它并不需要遍历所有的文件描述符组合，它的时间复杂度是 O(log n) 吧，然后相比来说性能会更好一些。

#### 3. 复盘判断

- 结论：基本正确，但复杂度表达不稳。
- 状态：`[learning] [interview]`
- 影响程度：中

#### 4. 推荐回答

> `select`、`poll`、`epoll` 都是 I/O 多路复用机制，用来让一个线程管理多个 fd。`select/poll` 的问题是每次等待事件时都要遍历一批 fd，连接数多时开销会变大；`select` 还有 fd 集合大小限制。`epoll` 的思路是先通过 `epoll_ctl` 把关注的 fd 和事件注册到内核，事件就绪后内核把它放到就绪队列，`epoll_wait` 返回的是已经就绪的事件，不需要每次从头扫描所有 fd，所以更适合大量连接但同一时刻活跃连接不多的场景。我的视频服务项目里用 epoll 管理多客户端连接，主要是避免一个慢客户端阻塞整个服务。

### 问题 9 · TCP 为什么四次挥手

#### 1. 面试官原问题

**面试官：** TCP 为什么要四次挥手？

#### 2. 我当时的回答（全文）

**我：**

> 首先就是我的一个客户端会向服务端发送一个断线的请求。服务端收到以后，会回复一个 ACK 的包。相当于发送完断开的请求，再发送这个 ACK 包之后，就相当于从客户端向服务端的这条链路已经断掉了。
>
> 然后后两次挥手，就是在服务端向客户端传输完数据以后，服务端再向客户端发送一个请求，然后客户端再发送一个 ACK 给服务端。后两次挥手就相当于把服务端向客户端的这个链路给断开。所以就需要四次挥手。

#### 3. 复盘判断

- 结论：基本正确，但用词不严谨。
- 状态：`[learning] [interview]`
- 影响程度：中

#### 4. 推荐回答

> TCP 是全双工连接，双方都有独立的发送方向，所以关闭时要分别关闭两个方向。以客户端主动关闭为例，客户端先发 `FIN`，表示自己不再发送数据；服务端回复 `ACK`，这时客户端到服务端这个发送方向关闭了。但服务端可能还有数据没发完，所以不能立刻关闭；等服务端数据发送完成后，再发自己的 `FIN`，客户端回复 `ACK`，服务端到客户端这个方向也关闭。通常是四次，是因为服务端对客户端 `FIN` 的确认和服务端自己的 `FIN` 不一定能合并。

> 右值引用，对，相当于就是一个 `std::move` 的东西，对吧？就是我可能现在记得有一点点不太清，但是我对它的印象就是它可以把这个右值，它是一个临时的对象嘛。然后在这个右值引用的过程中，我就不把它直接进行销毁。我可以把这个临时对象给它绑定到一个新的对象上。我对它的印象好像就是，它主要我在实习的过程中看到它一般的作用就是用来实现一些回调函数。

#### 3. 复盘判断

- 结论：答错 / 不会。
- 状态：`[weak] [wrong] [interview]`
- 影响程度：高

#### 4. 当时回答的问题在哪里

- 错误原话：`右值引用相当于 std::move 的东西`。
- 问题：`std::move` 只是类型转换，不等于右值引用本身。
- 错误原话：`不把临时对象直接销毁，绑定到新的对象上`。
- 问题：没有说出移动语义、资源接管、避免深拷贝。

- 问题：这是很偏的观察，不是核心用途。

> 右值引用是 C++11 引入的机制，形式是 `T&&`，核心作用是支持移动语义和完美转发。对我来说最重要的是移动语义：当一个对象内部持有堆内存、文件描述符等资源时，如果它是临时对象或即将不再使用，就没必要深拷贝资源，可以通过移动构造把资源所有权转移给新对象，然后把原对象置成安全可析构的空状态。`std::move` 本身不移动资源，它只是把对象转换成右值表达式，真正的资源转移发生在移动构造或移动赋值函数里。

### 问题 11 · 智能指针 / shared_ptr / 引用计数位置

#### 1. 面试官原问题

**面试官：** C++ 里有哪些智能指针？`shared_ptr` 是什么？引用计数放在哪里？

#### 2. 我当时的回答（全文）

**我：**

> 我记得是有这个共享指针，然后还有一个普通的，它也可以自动管理一些指针指向资源的 unique 指针，还有一个弱指针。
>
> shared_ptr 的话就是相当于我有多个指针都同时指向同一个资源。它这里起到的是多个对象可以共享同一份资源，然后在共享的过程中会维护一个引用计数，只有在它的引用计数归零的时候，才会把这个对象进行销毁。
>
> 引用计数的话我可能不太确定，但是如果让我认为的话，它应该是放在堆里吧。因为栈的话一般放的都是一些函数的传入参数和一些局部变量，然后我觉得这个引用计数应该是放在堆里的。

#### 3. 复盘判断

- 结论：shared_ptr 大方向基本正确；引用计数解释不完整。
- 状态：`[learning] [interview]`
- 影响程度：中

#### 4. 推荐回答

> 常见智能指针有 `unique_ptr`、`shared_ptr` 和 `weak_ptr`。`unique_ptr` 表示独占所有权，不能拷贝但可以移动；`shared_ptr` 表示共享所有权，多个 `shared_ptr` 可以共同管理同一个对象；`weak_ptr` 不增加强引用计数，主要用于观察 `shared_ptr` 管理的对象，也常用于解决循环引用。`shared_ptr` 通常有一个控制块，控制块一般在堆上，里面保存强引用计数、弱引用计数、删除器等信息。多个 `shared_ptr` 指向同一资源时共享同一个控制块，强引用计数归零时释放被管理对象，弱引用计数也归零后控制块才释放。

### 问题 12 · 用过哪些标准库 / vector 和 list 区别

#### 1. 面试官原问题

**面试官：** 用过哪些 C++ 标准库？`vector` 和 `list` 有什么区别？

#### 2. 我当时的回答（全文）

**我：**

> 就一些 iostream，还有 fstream，还有 list 这些东西。
>
> 我记得 vector 它底层是基于数组，然后 list 它底层是基于链表。数组的话，它要求内存连续，它的缺点就是必须得要求内存连续，但是我可以随机访问它不同位置上的数据，访问的时间复杂度是 O(1)。但是如果链表的话，它就不能够随机访问，时间复杂度平均下来可能偏 O(n)，因为它需要从链表的头节点一直向下遍历。

#### 3. 复盘判断

- 结论：基本正确但不完整。
- 状态：`[learning] [interview]`
- 影响程度：中

#### 4. 推荐回答

> `vector` 底层是连续内存，优点是支持下标随机访问、缓存友好、遍历效率高；缺点是中间插入删除可能移动后续元素，容量不够时扩容会重新分配并搬移元素。`list` 底层是链表，节点内存不连续，优点是已知位置时插入删除不需要移动大量元素；缺点是不支持随机访问，每个节点有额外指针开销，缓存局部性差。工程里如果主要是遍历和随机访问，一般优先用 `vector`；只有确实频繁在中间插入删除且已经持有位置时，才考虑 `list`。
