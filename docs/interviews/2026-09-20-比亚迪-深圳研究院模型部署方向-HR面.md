## 本场整体表现

### 做得比较好的部分

- 自我介绍覆盖教育、两段实习、两个 Linux 项目，HR 明确反馈“实习这块你刚刚介绍得非常清晰”，说明经历主线至少对 HR 是可理解的。
- 地点、学历、英语、薪资接受度等基本筛选项回答稳定，没有出现明显冲突。
- 自我评价使用了真实实习案例，而不是完全空泛的性格词。
- 对测试岗位没有简单说“都可以”，而是能把自己接受的测试方向连接到自动化平台和开发效率。

### 最影响结果的问题

1. `[weak] [interview]` 行为问题仍然习惯先铺背景再给结论，尤其“是否接受测试岗位”和“综合评价自己”明显过长。
2. `[weak] [interview]` 求职动机表达中出现“秋招锻炼表达能力”这类不必要的话，可能削弱真实求职意愿。
3. `[learning] [interview]` 反问需要匹配对象：HR 问流程/培养/岗位分配，技术面问模型部署技术栈和业务难点。

### 表达层面

- 是否经常没有先给结论：是，测试岗位、自我评价最明显。
- 是否展开过多：是，测试岗位约 1 分半，自我评价约 2 分半。
- 是否把“我不知道”之后的推理讲清楚：本场无此类技术问题。
- 项目题是否体现“问题 → 设计 → trade-off → 极端情况”：HR 面没有真正进入项目深挖，但自我评价里的案例仍缺“结果”。

### 技术层面

- C/C++：本场未验证。
- Linux / OS：本场未验证。
- 网络：本场未验证。
- 驱动 / 嵌入式：本场未验证。
- 项目设计：自我介绍只做概述，没有技术追问。
- Coding：本场未验证。

因此，这场 HR 面**不能用于判断技术面是否稳**。它对技术面真正有价值的地方，是已经把后续技术面最可能关注的入口暴露出来：两段 TBox 实习、V853、x86 OS，以及你主动强调的 Linux 方向。后续技术面应优先准备这些简历主线，并补一条“为什么从通信/AI研究转到模型部署与 Linux 系统工程”的桥接回答。
