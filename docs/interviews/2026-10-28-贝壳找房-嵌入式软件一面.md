### 问题 6 · 大模型与传统 CV 模型的区别 { #q6 }

#### 1. 面试官原问题

> 我们现在说的大模型，跟以前传统的 CV 模型主要区别是什么？不知道也没关系，我想看你了解的程度和自己的理解。

#### 2. 我当时的回答（全文）

> 我觉得首先一点是大模型突出在“大”，模型参数非常多。第二点是它们基于的架构不一样，比如大语言模型可能基于 Transformer 架构，其他 CV 模型可能偏 CNN，或者多层感知机和卷积神经网络这类架构。
>
> 原理上来讲，大语言模型更多偏生成模型，根据前几个 token 预测之后的 token；一些 CV 模型偏目标检测或者分类，根据拿到的数据推断属于哪个类别。
>
> 我理解主要存在模型参数、底层架构和面向功能的区别。如果从模型部署角度，大模型参数比较多，相比 CV 模型要考虑的问题更多，对设备内存和算力要求更高，所以可能需要把模型尽可能简单化，并通过推理框架优化减少资源开销。以上就是我对大模型和其他 CV 模型的一些了解。

#### 3. 现场反馈

> 你对大模型和传统 CV 模型的理解，这两点基本是对的，基本正确。

#### 4. 复盘判断

- 结论：基本正确
- 状态：`[learning] [interview]`
- 影响程度：中

#### 5. 当时回答的问题在哪里

- **正确的部分：** 参数规模、常见架构、生成/判别任务、部署资源压力都提到了；面试官明确认可“基本正确”。
- **需要修正：** “传统 CV = CNN/分类检测、大模型 = Transformer/生成”只是典型情况，不是严格边界；现代视觉基础模型也可使用 Transformer，CV 也有生成模型。
- **遗漏的关键点：** 训练范式、通用性/迁移方式、输入输出模态、上下文长度与 KV cache 等部署差异。

#### 6. 推荐回答（完整版本）

### 问题 8 · GPU 与 NPU 在模型推理中的区别 { #q8 }

#### 1. 面试官原问题

#### 2. 我当时的回答（全文）

> 关于 GPU，我的理解是它有很多计算单元，这些计算单元一般用来做矩阵运算。相比 CPU，它更多做一些比较简单的运算，但是因为可以进行并行计算，所以速度会比 CPU 快很多。
>
> NPU 主要更多面向模型推理，相比 GPU 会更加专用一点。具体硬件架构我有点记不太清。

#### 3. 现场反馈

> 没关系。一般使用 NPU 做推理，很少研究它的硬件架构，做高性能计算才会研究；一般把它用好就可以。

#### 4. 复盘判断

- 结论：方向基本正确，但过于概括
- 状态：`[learning] [interview]`
- 影响程度：中

#### 5. 当时回答的问题在哪里

- **正确的部分：** GPU 并行计算、NPU 更专用这两个核心方向正确。
- **表述不严谨：** GPU 不只是“做简单运算”；CPU/GPU/NPU 的性能不能脱离算子、精度、内存带宽、编译器和运行时支持直接比较。
- **遗漏的关键点：** NPU 通常面向张量/神经网络算子、低精度计算和能效优化，但算子覆盖、动态 shape、调试生态与可编程性常受平台限制；GPU 通用性和生态通常更强。

#### 6. 推荐回答（完整版本）

> GPU 是高吞吐并行处理器，适合大规模数据并行和矩阵计算，可编程性、算子生态和调试工具通常更成熟；NPU 是针对神经网络张量算子和常见低精度计算做专用优化的加速器，在受支持模型上往往有更好的能效和端侧性能，但算子支持、动态 shape、转换工具和运行时更依赖具体芯片厂商。实际部署不能只比较峰值算力，还要看模型算子是否全落在加速器上、是否发生 CPU fallback、量化精度、内存搬运以及端到端延迟。

- **重复薄弱证据：** 2026-08-13 字节面试已经在固定 1MB 内存上设计 allocator 时没有思路；本场换成“用没用过内存池”仍只能说目的，说明动态内存分配器/内存池不是单次失误，而是重复薄弱点。

#### 6. 推荐回答（完整版本）

> 我没有在正式项目里独立实现过内存池，这一点要说明。它通常先向系统申请一大块内存，再在内部用 free list、bitmap 或 size class 管理小块，减少频繁进入通用分配器的开销，并让分配延迟更稳定。固定大小对象可以用对象池或 slab 风格的固定块；尺寸分布较散时要处理 split、merge、对齐和外部碎片。多线程下还要考虑锁、线程本地缓存和跨线程释放。它不是一定更省内存：size class 可能带来内部碎片，生命周期和需求不稳定时也会长期占住峰值内存，所以要基于对象尺寸、频率和时延要求决定是否使用。
