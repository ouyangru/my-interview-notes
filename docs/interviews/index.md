# 面试复盘

这里保存每一次真实面试的现场记录。重点不是把面试重新整理成一份漂亮的“标准答案”，而是完整保留“被问了什么、当时到底怎么答、哪里出了问题、下一次应该怎么答”。

建议文件名统一使用：`YYYY-MM-DD-公司-岗位.md`，例如 `2026-09-15-某公司-嵌入式软件.md`。

统一模板：[面试复盘模板](../templates/interview-review.md)

## 固定复盘原则

1. 面试官原问题尽量保留全文和上下文。
2. **“我当时的回答”必须保存完整原回答，不能压缩成几句概括。**
3. 原始回答中的错误、犹豫、自我修正不要偷偷改掉；这些就是判断问题所在的依据。
4. 原始转写如果缺失，只能标 `[转写缺失]` / `[听不清]` / `[无法确认]`，不能补造原话。
5. “当时回答”和“推荐回答”必须分开。
6. 推荐回答也要写成下一次面试能直接说出口的完整版本，不能只列关键词。
7. 每道题都要明确定位：哪些句子是对的、哪里错、漏了什么、为什么面试官会继续追问。
8. 相关长期知识点放链接，不把整份复盘再次复制到 `knowledge/`。

## 每道题的固定结构

1. 面试官原问题
2. 我当时的回答（全文）
3. 现场继续追问与我的回答（全文）
4. 复盘判断
5. 当时回答的问题在哪里
6. 推荐回答（完整版本）
7. 当时回答 vs 推荐回答
8. 关联知识库
9. 项目 / 实习连接
10. 下一次应该怎么追问

## 复盘流程

1. 先按实际顺序还原面试现场，不急着整理成标准答案。
2. 对每道题标记：答对 / 基本正确 / 不完整 / 答偏 / 答错 / 不会。
3. 从完整原回答中定位具体错误句、遗漏点和表达结构问题。
4. 给出完整推荐回答。
5. 把真正值得长期复用的问题沉淀到 [个人知识库](../knowledge/index.md)。
6. 把本场最影响结果的 2～3 个问题同步到 [当前能力状态](../knowledge/STATUS.md)。
7. 在面试复盘和知识页之间互相建立链接。
