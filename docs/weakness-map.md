## 重复薄弱点判断

### 6. CAN / I²C 已确认是重复薄弱点

2026-09-10 恒玄一面已经暴露 I²C START/STOP 与 CAN ID/仲裁不稳，2026-09-21 Sharpa 一面再次出现同类问题：CAN “抢占”答成软件队列，I²C 多从机通信仍无法完整说出时序。因此后续训练必须按重复薄弱点处理，优先级升到 P0。

训练要求：不能只背四协议表格，必须能从真实场景回答“谁发时钟、怎么选从机、什么时候 ACK、总线同时发怎么办、Linux 应用队列和硬件总线仲裁是什么关系”。

### 7. V853 的薄弱点从“慢客户端策略”升级为“端到端故障定位”

此前已经能讲独立队列和丢旧帧，但 Sharpa 一面说明这还不足以证明项目掌握。下一轮必须能回答延迟与花屏如何定位，至少包含：frame id、monotonic timestamp、逐层 dump、H.264 关键结构、TCP partial send/EAGAIN/buffer 生命周期、客户端交叉验证。

### 8. 基础 Coding 需要先做题意确认，再谈算法

Sharpa 的 substring 题不是因为不会 KMP，而是先把 substring 和 subsequence 定义混淆，又出现指针对象和 return 边界错误。后续 Coding 训练在写代码前增加 10 秒 sanity check：是否连续、谁是大串、成功条件是谁走到末尾、失败时哪个指针移动、提前输出后是否 return。

### 9. 网络知识不能再停留在单个协议八股

2026-09-21 比亚迪蜂窝网络通信方向一面中，面对“手机点开视频后的完整网络数据路径”，只回答了客户端请求和服务器推流，并先误判成 Android 平台题。面试官随后直接补出 DNS、TCP、IP、Modem、基站、核心网和服务器。由于简历同时写有 Socket、TCP/UDP/HTTP、TBox，专业又是通信，这不是单次漏词，而是知识仍按单协议孤立存放，没有形成端到端系统图。

训练要求：90 秒内稳定口述“蜂窝已联网 → DNS → TCP/QUIC → TLS/HTTP → IP → Modem → 基站 → 核心网 → 公网/CDN/服务器 → 返回 → 缓冲/解码/渲染”；随后随机从 DNS、TLS、路由、Modem 或核心网任一点向下追问。

### 10. ownership 边界已跨研究、V853 和 TBox 重复暴露

研究方向先讲成真实“边缘设备采集并无线传输”，直到追问才说明是公开数据/MATLAB 与信道模型；V853 先说“推到电脑”，直到追问才说明开源静态 HTTP 基线、板端服务端和 PC 客户端；MSD 也容易把标准数据本体、外层 TCP 报文和本人登录/心跳/解析职责混在一起。

训练要求：所有项目固定用四层回答——“整体系统 / 开源或平台现成部分 / 我亲手实现部分 / 明确未做部分”。能讲整体不等于拥有每一层；承认边界后必须立刻给出本人实现的具体证据。



### 1. 模式识别不是单题失误

本轮至少 7 个题目重复出现“先写复杂实现，后面才发现模型不对”的现象，因此按重复薄弱点处理，而不是单题偶发错误。

训练要求：每题写代码前先口述：

1. 暴力是什么；
2. 暴力复杂度；
3. 重复工作；
4. 经典触发器；
5. 状态定义。

### 2. 实现稳定性不是单纯粗心

`sort` 区间、下标、vector 复制、栈清空、递归恢复等错误跨多题重复出现，需要单独统计。后续训练中应把错误分成两类：

- 模型错误：算法/状态本身不成立；
- 实现错误：模型成立，但 C++ 代码不可靠。

### 3. 当前不能因为“看懂答案”升级状态

这轮多个算法已经能在讲解后理解，但还没有经过新的换皮题独立识别，因此滑动窗口、单调栈、Dijkstra、Hierholzer、二分答案等仍保持 `[weak]`；只有在后续独立完成后再升级为 `[learning]` / `[stable]`。

## 下一轮训练配比

- 60%：`[weak]` / 重复错误——模式识别、滑动窗口单调性、区间操作不变量、单调栈、图算法边界、状态扩图、实现稳定性。
- 25%：`[learning]`——背包/pair 拆分、滚动 DP、加权中位数。
- 15%：稳定回测——BFS、普通 Dijkstra 基础模板、基础回溯。

### 4. 贪心交换新增为模式识别薄弱点

2026-09-19 的种类奖励题再次出现“先进入实现，后发现状态不够”的模式：先尝试 `dp[i][j]`，但 j 只记录种类数量，无法判断具体类型是否已出现。讲解后已经理解“基础最优解 → 增加一次奖励需要什么交换 → 让交换代价最小”的推导，但尚未独立完成换皮题，因此保持 `[weak]`。

后续训练要求：遇到“固定选 K 个 + 基础收益 + 附加奖励”时，写代码前先口述三问模板，并明确为什么被删除元素必须是冗余项。


### 5. 二分答案开始从 weak 向 learning 过渡

2026-09-20 的轮数最小化题中，用户已经独立写出二分边界与 `check(count)` 的主体模型，说明“猜答案 + 单调可行性”开始形成；但 check 内仍把普通整除误认为向上取整，并漏掉 `need == count` 的合法边界。因此仅升级到 `[learning]`，并保留 `[wrong]` 历史，后续必须通过换皮题独立写对取整和等号才可继续升级。
