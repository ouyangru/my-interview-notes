## 题目一：P5428 作业限放接单

### 题面核心

给定作业耗时数组 `arr`，从左到右依次审阅，每项可以跑掉或放掉。必须刚好跑 `t` 个；连续放掉的作业数不能超过 `lim`；目标是所跑作业耗时和最小；`n <= 1000`。

### 我的初始思路

最开始想直接设计二维 DP，并把“已经跑了几个”和“总耗时”塞进 Node：

```cpp
struct Node{
    int total_number;
    int time;
};
vector<vector<Node>> dp(lim+1, vector<Node>(size+1,{0,-1}));
```

同时尝试提前判断：

```cpp
if(size==0 || size<(lim+1)*t)
```

但没有理清状态转移。

### 正确状态模型

`dp[j][i]`：已经选了 `j` 个作业，并且第 `j` 个选中的作业恰好是位置 `i` 时的最小耗时。

若上一个选中位置是 `k`，连续放掉限制要求：

```text
i-k-1 <= lim
=> k >= i-lim-1
```

所以朴素转移：

```cpp
dp[j][i] = arr[i] + min(dp[j-1][k]);
// i-lim-1 <= k < i
```

直接枚举 `k` 为 `O(t*n*lim)`；而这里的 `min(dp[j-1][窗口])` 是固定长度滑动窗口最小值，可用单调队列优化到 `O(t*n)`。

### 可行性提前判断

选 `t` 个后有 `t+1` 段可放掉空隙，每段最多 `lim` 个，因此必须满足：

```cpp
if (n - t > (t + 1) * lim) return -1;
```

原来的 `size < (lim+1)*t` 不是正确约束。

### 暴露问题

- `[weak]` 状态定义前就开始写结构体和 DP 数组；
- `[weak]` 没先问“哪些历史信息会影响下一步是否合法”；
- `[learning]` 已理解“恰好选 j 个 + 最后位置 i”的状态；
- `[learning]` 已理解窗口最小值可用单调队列优化。

## 题目二：固定间隔选 t 个位置并统计合法方案

> `[题面缺失]`：已知参数 `m,t,g,lo,hi`。从 `1..m` 选恰好 `t` 个下标，相邻选择之间至少隔 `g` 个位置，对应权值和落在 `[lo,hi]`；统计方案数并保留前 3 组。

### 第一版思路

直接写死三层循环：

```cpp
for(int i=1;i<m-2*(g+1);i++){
    for(int j=i+g+1;j<m-g-1;j++){
        for(int k=j+g+1;k<=m;k++){
            if(mVec[i]+mVec[j]+mVec[k]>=lo &&
               mVec[i]+mVec[j]+mVec[k]<=hi){
                count++;
            }
        }
    }
}
```

### 第一版问题

1. `[wrong]` `t` 是输入变量，但三层循环只能处理 `t==3`，模型本身不通用；
2. `< / <=` 有 off-by-one，可能漏掉刚好贴边的合法组合；
3. `vector<vector<int>> mResult(4)` 只有外层大小，内层仍为空，合法方案不足 3 组时访问 `mResult[i][0]` 会越界/段错误。

### 修正后的 DFS

```cpp
vector<int> chosen;
int cnt = 0;
vector<vector<int>> top;

void dfs(int start, int total) {
    if ((int)chosen.size() == t) {
        if (lo <= total && total <= hi) {
            cnt++;
            if ((int)top.size() < 3) top.push_back(chosen);
        }
        return;
    }

    int remain = t - (int)chosen.size();
    for (int i = start; i <= m; i++) {
        chosen.push_back(i);
        dfs(i + g + 1, total + w[i]);
        chosen.pop_back();
    }
}
```

### DFS 的真实状态

表面参数是 `start,total`，实际还依赖全局 `chosen`：

```text
start          下一次最早从哪里选
chosen.size()  已经选了几个
total          当前权值和
chosen         当前完整路径
```

`chosen` 是所有递归层共享的路径，所以必须执行 `push_back -> dfs -> pop_back` 恢复状态。`cnt/top` 是全局统计结果，不需要回溯。

### 更强剪枝

如果从当前 `i` 开始还需选 `remain` 个，最紧凑位置是 `i, i+(g+1), ...`，因此可判断：

```cpp
if (i + (remain - 1) * (g + 1) > m) break;
```

### 暴露问题

- `[wrong]` 动态 `t` 被硬编码成固定层数；
- `[weak]` 对 DFS 的隐藏全局状态和回溯恢复不熟；
- `[weak]` `< / <=`、空 vector 访问等实现边界继续反复出现；
- `[learning]` 已理解 `start / chosen / total` 各自保存什么。

## 题目三：二分答案 + 额外操作次数判断

> `[题面缺失]`：已知每轮所有元素至少获得 `B` 的固定效果，同时每轮可对一个元素获得总计 `A` 的效果，因此被特殊处理元素相对公共效果多获得 `A-B`。目标是求最少轮数。

### 我的代码核心

```cpp
bool can_cold(int count, vector<int>& mVec){
    int fix_value = count * B;
    int need_count = 0;
    for(int i=0;i<N;i++){
        need_count += max(mVec[i]-fix_value,0)/(A-B);
    }
    return need_count < count;
}
```

二分框架本身已经写出来：猜 `count`，若可行就收缩右边界，否则抬高左边界。

### 正确 check 模型

假设总轮数为 `count`，每个元素先获得 `count*B` 的公共效果。若仍剩 `remain`，每次特殊操作只能额外提供 `A-B`，所以该元素需要：

```cpp
ceil(remain / (A-B))
```

次特殊操作。所有元素需要的特殊操作总数不超过 `count` 时，该轮数可行。

### 错误一：普通整数除法不是向上取整

我当时明确误以为 `remain/(A-B)` 已经是向上取整。实际上 C++ 正整数整数除法会向下取整，例如 `4/3 == 1`。

正整数向上取整：

```cpp
(x + y - 1) / y
```

因此应写：

```cpp
need += (remain + extra - 1) / extra;
```

### 错误二：应该允许恰好用满 count 次

原来：

```cpp
need_count < count
```

正确是：

```cpp
need_count <= count
```

### 更稳的 check

```cpp
bool can_cold(long long count, const vector<int>& a) {
    long long extra = A - B;
    long long need = 0;
    for (int x : a) {
        long long remain = max(0LL, 1LL*x - count*B);
        if (remain > 0) {
            need += (remain + extra - 1) / extra;
        }
        if (need > count) return false;
    }
    return true;
}
```

这里使用 `long long`，避免 `count*B` 和累计次数潜在溢出。

### 暴露问题

- `[learning]` 已能独立写出二分答案主框架；
- `[wrong]` 把普通整数除法误认为向上取整；
- `[weak]` `< / <=` 边界依然高频出错；
- `[weak]` check 内应主动检查整数溢出与取整方向。
