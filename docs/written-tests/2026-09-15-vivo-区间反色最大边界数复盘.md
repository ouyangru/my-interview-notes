## 题目

已确认条件：

- 给定长度为 `n` 的二进制字符串 `s`；
- 一次操作选择一个连续区间，将区间内所有字符 `0/1` 反色；
- 字符串第一个和最后一个字符不能被反色，因此区间必须完全位于内部；
- 最多执行 `k` 次操作；
- 边界指相邻两个字符不同的位置；
- 求最多能够得到多少个边界。

约束从截图可确认：`2 <= n <= 2*10^5`，`0 <= k <= 2*10^5`，所有测试的 `n` 之和不超过 `2*10^5`。

样例中可确认：

```text
0110111, k=2 -> 5
111111,  k=2 -> 4
```

## 我的现场思路

我按原字符串的连续 `0` 段和连续 `1` 段分类，希望把“偶数长度连续段”和“长度大于 2 的奇数连续段”分别统计，再判断每次操作可以从不同连续段中制造多少个新边界。

考后讨论 `0011001` 时，我仍然倾向于从原始连续段角度解释：把连续 `0/1` 看成可提供新增边界的资源，并按段长奇偶性计算机会数。

## 判断

`[wrong] [weak]`

并不是连续段观察完全无效，而是状态选得过重，而且原始 run 结构不是操作下的不变量。一次区间反色以后，原来的连续段会被拆分、合并或改变颜色，继续按“原始 0 段 / 1 段”计数会让状态越来越难维护。

本题真正稳定的对象不是字符段，而是 **相邻关系**。

## 正确抽象：边界数组

定义：

```text
b[i] = (s[i] != s[i+1]),  0 <= i < n-1
```

`b[i]=1` 表示这里已经是边界，`b[i]=0` 表示两个相邻字符相同。

若反色内部区间 `[l,r]`，区间内部任意一对相邻字符会同时反色，因此“相同/不同”的关系不变。真正改变的只有区间左右两侧：

```text
(l-1,l) 与 (r,r+1)
```

也就是说，一次合法操作恰好翻转边界数组中的两个位置：

```text
b[l-1] ^= 1
b[r]   ^= 1
```

由于首尾字符不能反色，任意两个边界位置 `p<q` 都可以通过反色 `[p+1,q]` 同时翻转。

## 最优策略

设当前边界数为 `boundary`，则边界数组中 `0` 的数量为：

```text
same = (n-1) - boundary
```

若还能找到两个 `0`，一次操作选它们作为两个端点，就能同时变成两个 `1`，边界数增加 `2`。

因此最多进行：

```text
min(k, same/2)
```

次有效 `+2` 操作，最终答案：

```cpp
boundary + 2 * min(k, same / 2)
```

时间复杂度 `O(n)`，只需要扫描字符串一次。

## 代码

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;

    while (T--) {
        int n, k;
        string s;
        cin >> n >> k >> s;

        int boundary = 0;
        for (int i = 0; i + 1 < n; ++i) {
            if (s[i] != s[i + 1]) ++boundary;
        }

        int same = (n - 1) - boundary;
        cout << boundary + 2 * min(k, same / 2) << '\n';
    }
}
```

## 关键反例：为什么不要维护原始连续段

例如：

```text
000011, k=2
```

初始只有一个边界。若从原始 run 看，是 `0000 + 11`，很容易开始讨论两个 run 的奇偶长度和“各自还能贡献几次”。但连续段本身会被操作改变：

```text
000011
-> 011011   （反色内部区间 [2,3]，边界 +2）
-> 010101   （再反色一个内部区间，边界再 +2）
```

最终可达到 `5` 个边界。更稳定的解释是：初始边界数组中有 4 个 `0`，两次操作每次消掉两个 `0`，直接得到 `1 + 2*2 = 5`。

## 暴露的问题

1. **操作题没有先找不变量。** 我直接研究字符段如何变化，却没有先问“区间整体反色以后，哪些局部关系一定不变”。
2. **状态过重。** 原始 run 的颜色、长度、奇偶性都被纳入状态，但答案其实只依赖 `n-1` 个相邻关系。
3. **没有先分析单次操作到底影响几个位置。** 本题一次区间操作虽然看起来改了很多字符，但对目标函数只影响两个端点。

## 以后遇到类似题的固定检查

看到“对一个连续区间整体做同一种可逆操作”时，先不要模拟区间内部，而是依次问：

1. 区间内部的相邻关系、差值、异或、奇偶性是否保持不变？
2. 单次操作对目标函数真正改变的是整段，还是只有端点？
3. 能否把原序列转换成差分数组 / 边界数组 / 异或数组，使一次区间操作变成少数几个点修改？

本题对应的条件反射是：

```text
区间整体反色 + 目标统计相邻是否不同
→ 看相邻异或 / 边界数组
→ 区间内部不变，只翻两个端点
→ 计数题
```
