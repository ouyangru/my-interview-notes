## 题目一：树苗生长后判断矩形封闭结构

### 题面核心

棋盘为 9×9。每棵树苗给出初始坐标、上下左右生长方向与最大生长长度；树苗按配置生长并占据格子。当前截图能确认的定义是：存在一个轴对齐矩形，其四条边完全由树苗组成；题面没有要求矩形内部必须为空。

### 我的初始思路

1. 先用 mVisited[9][9] 模拟所有树苗最终占据的格子；
2. 用 row / lie 记录哪些行或列可能成为矩形边；
3. 找到候选的左右/上下边界；
4. 再逐格检查四条边是否全部被占据。

现场代码中最关键的片段：

```cpp
for (int j = up + 1; j < 9; i++) {
```

以及：

```cpp
while (!mVisited[x][y] && y - config.y < config.maxGrowLength && y < 9) {
    mVisited[x][y] = true;
    y++;
}
```

### 现场结果

提交表现：TLE。

### 复盘判断

整体方向“先模拟最终棋盘，再判断矩形”是可行的，但后半段为了先推断候选边界引入了不必要的状态。当前 TLE 的直接原因不是算法复杂度，而是实现中的死循环。

### 明确错误

#### 1. j++ 写成了 i++，直接形成死循环 [wrong]

```cpp
for (int j = up + 1; j < 9; i++)
```

循环条件检查的是 j < 9，但 j 从不变化，只要进入循环就可能永久执行。应改为：

```cpp
for (int j = up + 1; j < 9; j++)
```

这次错误归类为实现稳定性问题，不是算法不会。

#### 2. 数组访问发生在边界判断之前

例如：

```cpp
while (!mVisited[x][y] && ... && y < 9)
```

C++ 的 && 从左到右短路求值，因此当 y == 9 时会先访问 mVisited[x][9]，已经越界。固定规则是把边界放到数组访问之前，例如：

```cpp
while (y < 9 && ... && !mVisited[x][y])
```

所有 x >= 0、x < 9、y >= 0、y < 9 都应该先于数组访问。

#### 3. maxGrowLength 存在 off-by-one 风险

从截图描述看，最大生长长度不包含初始树苗格，因此长度为 L 时应覆盖“初始格 + 最多 L 个新格子”。当前使用 < maxGrowLength 会少覆盖一格，需要按题意核对为 <= maxGrowLength，并结合棋盘边界截断。

#### 4. Up / Down 的坐标增减需要和题目坐标系重新核对

当前代码中 Up -> y++、Down -> y--，但截图示例表现出的坐标方向与此可能相反。应以题面给定坐标系为准，不要按屏幕视觉习惯猜方向。

#### 5. 函数末尾缺少 return false

没有找到矩形时应显式返回 false，否则非 void 函数走到末尾属于未定义行为。

#### 6. 搜索首个候选行/列时仍可能越界

例如 while (!row[right]) right++; 若根本不存在候选，会继续访问 row[9]。必须先判断 right < 9。

## 更简单的标准做法：枚举矩形四条边

棋盘只有 9×9，没必要预先维护 row/lie。直接枚举左边界 x1、右边界 x2、上边界 y1、下边界 y2，共 C(9,2)×C(9,2)=1296 个矩形候选，每个候选只检查四条边。

```cpp
for (int x1 = 0; x1 < 9; ++x1) {
    for (int x2 = x1 + 1; x2 < 9; ++x2) {
        for (int y1 = 0; y1 < 9; ++y1) {
            for (int y2 = y1 + 1; y2 < 9; ++y2) {
                bool ok = true;

                for (int x = x1; x <= x2; ++x) {
                    if (!tree[x][y1] || !tree[x][y2]) {
                        ok = false;
                        break;
                    }
                }

                if (ok) {
                    for (int y = y1; y <= y2; ++y) {
                        if (!tree[x1][y] || !tree[x2][y]) {
                            ok = false;
                            break;
                        }
                    }
                }

                if (ok) return true;
            }
        }
    }
}
return false;
```

### 我的理解修正

这题当时想复杂了。既然棋盘大小是常数级 9×9，应该优先问“能不能直接枚举所有合法结构”，而不是先设计额外状态筛候选。这里暴力枚举矩形反而是最稳、最清晰的标准解。

### 如果题意真的是“被围住的空白区域本身必须是矩形”

那么“先找空地，再判断是不是矩形”的直觉是成立的，但更适合用 BFS/DFS + bounding box，而不是 row/lie。对每个未访问空格做 BFS/DFS，统计 minX、maxX、minY、maxY、连通块格子数 cnt 以及是否接触棋盘外界；如果空白连通块封闭且：

```cpp
cnt == (maxX - minX + 1) * (maxY - minY + 1)
```

则说明该连通块恰好填满自己的最小外接矩形，没有凹陷。再根据题意决定是否额外检查外围一圈全部为树。

### 错误类型

- [wrong] 循环变量写错导致死循环；
- [weak] 边界检查与数组访问顺序；
- [weak] 小数据范围下仍过度设计候选状态；
- [learning] 已经理解固定 9×9 时直接枚举所有矩形比 row/lie 更可靠。

## 题目二：IPv4 字符串转十六进制字符串

```text
176 -> B0
67  -> 43
2   -> 02
4   -> 04

结果：B0430204
```

## C++ 字符串 / 数值转换补充

本次讨论暴露出对 stringstream 不熟。

### string -> int

```cpp
string s = "176";
int x = stoi(s);
```

使用 stringstream：

```cpp
string s = "176";
stringstream ss(s);
int x;
ss >> x;
```

手写十进制解析：

```cpp
int x = 0;
for (char c : s) {
    x = x * 10 + (c - '0');
}
```

### int -> string

```cpp
int x = 176;
string s = to_string(x);
```

或：

```cpp
stringstream ss;
ss << x;
string s = ss.str();
```

### 利用流直接输出十六进制

```cpp
int num = 176;
stringstream ss;
ss << uppercase << hex << setw(2) << setfill('0') << num;
string s = ss.str();  // "B0"
```

不过在 IPv4 题里，手写 num/16 和 num%16 完全合理；问题不在于必须改用 stringstream。

## 本次暴露的长期问题

### 1. C++ 实现稳定性仍然是重复薄弱点 [weak]

这次再次出现 for 循环变量写错导致 TLE，和此前 sort(end,begin)、下标、容器层级、递归恢复等属于同一类问题。提交前固定检查：循环初始化/条件/递增变量是否一致；所有数组访问前是否先做边界判断；< 与 <= 是否符合题意；非 void 函数所有路径是否 return；坐标方向是否和题意一致。

### 2. 小规模题先尝试直接枚举所有结构 [weak]

当棋盘只有 9×9 时，应先估算完整枚举数量。本题只有 1296 个矩形候选，直接暴力检查就是最稳方案。

### 3. 字符串与数值转换 API 需要补基础 [learning]

目前手写转换能理解，但 stoi、to_string、stringstream、hex、setw、setfill 的常用法不熟。后续要做到看到“字符串 ↔ 整数 ↔ 进制格式化”时能快速选择稳定实现。
