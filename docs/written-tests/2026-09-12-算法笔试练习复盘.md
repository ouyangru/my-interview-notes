## 总体判断

这轮最大的暴露点不是“某个算法完全不会”，而是 **模式识别慢 + 过早进入实现层 + 状态定义不完整**。

反复出现的路径是：

1. 先根据题面表象选一个数据结构（堆、入度、二维矩阵、DFS）；
2. 没先用数据范围排除暴力；
3. 没先问“为了决定下一步，状态最少需要保存什么”；
4. 代码写到一半才发现模型不够，又继续补字段/分支，导致实现越来越复杂。

本轮已经能在提示后理解大多数标准模型，但暂时不能据此判定掌握，后续需要用换皮题回测。

## 1. BFS 与拓扑排序辨析

### 我的初始状态

对 BFS 和拓扑排序的边界不稳定。学习拓扑排序后，看到图题容易下意识往“入度/出度”上套。

### 判断

`[weak]`

### 正确思路

- BFS：从一个起点按层扩散；无权图最短路、最少步数、层数。
- 拓扑排序：处理有向无环图中的依赖关系；核心是“入度为 0 才可执行”。
- 不能因为题目是图就考虑拓扑排序，必须先看目标是否是“依赖/先后关系”。

### 暴露问题

算法名称能理解，但触发条件还没有形成稳定反射。

## 2. P5292 护栏补强：最大化最小值

### 我的初始思路

想用小根堆维护当前最矮位置，每次取最矮节点，再选择附近一段执行一次 `+1`。

### 判断

`[weak]`：方向符合“优先补最矮”，但没有先看 `T <= 1e9`，逐次模拟必然超时。

### 正确思路

- 关键词：**最大化最小值** → 优先检查能否“二分答案”。
- 猜最终最小高度 `X`，判断是否能在 `T` 次内全部抬到 `X`。
- 从左到右扫描，当前位置不够时一次补足 `need`，并尽可能覆盖右侧 `W` 个位置。
- 区间批量 `+need` 用差分/活动增量维护。

### 易错点

- 先模拟每次施工，而不是先检查数据范围。
- 堆只能快速取最小值，并不能自然解决大量区间加。

### 触发规则

`最大化最小值 + 区间加 → 二分答案 + 差分/扫描`

## 3. P5293 驿站补给最短耗时：状态扩图

### 我的初始思路

尝试从终点倒序 DP：`dp[i] = {battery, time}`，先算后面站点到终点，再向前推；同时把双向边按编号变成“小编号 → 大编号”。认为“到终点剩余电量越少，说明充电越少”。

### 判断

`[wrong] [weak]`

### 核心错误

1. 双向道路不能按节点编号强行定向；最优路径可能出现编号回退。
2. `dp[i]` 只保存一个电量状态不够。同一驿站“耗时更少但电量低”和“耗时略高但电量高”都可能在后续成为最优。
3. 最终剩余电量少不代表充电少，更不代表耗时少。
4. `battery % B` 没有物理意义，满电 `B` 甚至会被取成 0。

### 正确思路

将状态扩展为：

`(station, battery)`

两类状态转移：

- 充一格：`(u,b) -> (u,b+1)`，代价 `s[u]`
- 走路：`(u,b) -> (v,b-a)`，代价 `w`

所有代价非负，因此在这张扩展图上跑 Dijkstra。

### 触发规则

`到同一个位置，但携带的资源不同会影响未来 → 资源必须进入状态 → 状态扩图 + BFS/Dijkstra`

## 4. P5294 和差方程：图上传播关系

### 我的初始疑问

第一反应是线性方程组/矩阵运算，询问是否需要现成矩阵 API；随后意识到变量可能分成多个互不相连的部分。

### 判断

`[learning]`

### 正确思路

每条关系只连接两个变量，而且系数只有 `+1/-1`。在一个连通块中任选根变量 `t`，所有变量都可写成：

`x_i = sign_i * t + bias_i`，其中 `sign_i ∈ {+1,-1}`。

- 差关系 `x_u - x_v = d`：从 `u` 推 `v` 时，符号不变，常数减 `d`。
- 和关系 `x_u + x_v = s`：从 `u` 推 `v` 时，符号翻转，常数变为 `s-bias_u`。
- 已访问节点若得到第二个表达式，则用于检查矛盾或反推出 `t`。
- 每个连通块拥有自己独立的自由参数；若块内没有方程确定它，需要实测 1 个样品，否则贡献 0。

### 暴露问题

容易把“很多变量”直接联想到通用矩阵，而没有先利用“每个方程只连接两个变量”的稀疏结构。

## 5. P5279 最长匀差脉冲：状态变量定义

### 我的初始实现

已经想到逐相邻差值扫描，但代码中用 `if(gap)` 判断是否初始化，`count` 的含义在“差值个数”和“原数组长度”之间不稳定。

### 判断

`[learning]`

### 主要错误

- `gap == 0` 是合法公共差值，不能把 0 当作“未初始化”。
- `count` 应明确表示“当前段原数组元素数量”或“差值数量”，不能中途混用。
- 还需要同步记录最优左端点和最优公共差值。

### 正确模型

先形成差值序列：

`d[i] = (x[i+1]-x[i]+K)%K`

然后求 `d` 的最长连续相同段。若差值段长度为 `q`，对应原数组段长度为 `q+1`。

### 暴露问题

算法方向已对，但变量语义未先钉死，导致代码实现困难。

## 6. 网格最小代价：滚动 DP

### 我的初始实现

使用 `pre_dp` 和 `dp` 两行滚动数组，状态转移本身基本正确。

### 判断

`[learning]`

### 主要实现错误

- 把 `pre_dp` 整个 vector 和单个整数混用。
- 最终把一维 `dp` 按二维 `dp[r][c]` 访问。
- 没有统一考虑 `r=1` 的边界。

### 正确模型

`dp[j]` 原地滚动即可：更新前 `dp[j]` 代表上方，更新后的 `dp[j-1]` 代表左侧。

### 触发规则

`dp[i][j] 只依赖上一行同列和当前行左侧 → 可压缩为一维滚动数组`

## 7. P5309 鲤鱼离岛：最短路 + 最短路 DAG 上 DP

### 我的初始状态

无明显思路。

### 判断

`[weak]`

### 正确思路

1. 网格上下左右、每步代价相同 → BFS 求 `dist[x][y]`。
2. 先按 `(最短步数, 终点行, 终点列)` 确定唯一出口。
3. 只保留 `dist[next] = dist[cur]+1` 的边，得到最短路分层 DAG。
4. 在这个 DAG 上 DP，比较 `(rowSum, colSum)`，并记录 `parent` 恢复路径。

### 触发规则

`先要求最短；若最短路径有多条，再按额外指标选最优 → 最短路 + 最短路子图/DAG 上 DP`

## 8. 加权曼哈顿距离：加权中位数

### 我的初始思路

已经正确想到 x/y 分开处理、相同坐标合并权重、排序后找累计权重过半的位置；疑惑题目最终问的是目标值而不是点，所以是否还需要再遍历求值。

### 判断

`[learning]`

### 正确思路

- x、y 两个维度完全独立。
- `Σ w_i |x_i-X|` 的最优 `X` 是加权中位数：第一个满足 `prefixWeight * 2 >= totalWeight` 的坐标即可。
- 找到最优点后再扫描一次求目标值是正常且必要的。

### 实现易错点

- `cin >> a,b,w` 应写成 `cin >> a >> b >> w`。
- `map[key] += w` 可直接完成合并，无需 `find`。
- 极限答案可能超过 `long long`，需 `__int128`。

## 9. P5315 独占亮源：单调栈

### 我的初始思路

已经想到使用单调栈，分别求左右最近的“不低于当前值”的位置。

### 判断

`[learning]`

### 主要错误

- 哨兵使用 `200001`，但读数可到 `1e9`，可能被弹掉后空栈访问。
- 清空栈条件写成 `while(mStack.empty())`，应为 `while(!mStack.empty())`。
- 左右扫描时可只存下标，不必存 `{value,index}`。

### 正确触发

`左/右最近第一个 >= / > / <= / < 当前值 → 单调栈`

严格关系要注意弹栈条件。本题要求当前值严格大于邻居，因此相等值必须作为阻挡点保留。

## 10. P5316 区间上下界：扫描线 + 堆

### 我的初始实现

直接对每条 `[L,R]` 遍历区间内所有位置，分别更新 `min` 上界和 `max` 下界。

### 判断

`[weak]`

### 核心问题

`w,x,y <= 2e5`，区间逐点更新最坏约 `O(w(x+y))`，不可接受。

### 正确思路

从左向右扫描位置：

- 所有当前生效的上界操作放入小根堆，堆顶给当前最小 `hi`。
- 所有当前生效的下界操作放入大根堆，堆顶给当前最大 `lo`。
- 堆元素同时记录右端点，过期后弹出。

### 触发规则

`大量区间覆盖 + 每个位置要当前所有覆盖值的 min/max → 扫描线 + 堆（或线段树）`

## 11. 麻将胡牌：回溯与状态恢复

### 我的初始实现

按每门牌数量 `%3` 分类，再手写对子/刻子/顺子的多种分支。

### 判断

`[weak]`

### 主要错误

- `mOrder={Wan,Tong,Tiao}` 在读牌前复制，后续三个原 vector 更新不会同步。
- 数字牌字符映射写错，如 `token-1`、`Wan[token]`。
- DFS 修改计数后没有完整恢复状态。
- `i+1/i+2` 存在越界风险。
- `check()` 部分路径没有 return。
- 摸牌后总牌数/状态没有同步。

### 更简单的正确模型

将 27 种牌编号为 `0..26`。枚举摸牌后，DFS 每次找第一张剩余牌，它只有三种角色：

1. 对子（且只能有一对）；
2. 刻子；
3. 同花色顺子。

每次“修改 → 递归 → 恢复”。

### 触发规则

`组合拆分 + 总规模很小 + 每个元素只有少数角色 → 回溯，不要提前手写大量分类`

## 12. P5413 基站干扰指数：最近更大元素

### 我的初始思路

只能想到对每个位置向左右最多扫描 `t` 个；随后尝试单调栈，但左右栈和输入处理写乱。

### 判断

`[weak]`

### 正确思路

先完全忽略窗口 `t`，用单调栈分别求：

- 左边最近严格更大的位置；
- 右边最近严格更大的位置。

然后最后检查距离是否 `<=t`。

### 触发规则

`每个元素向左/右找最近第一个更大/更小 → 单调栈`

这是本轮最需要形成条件反射的模式之一。

## 13. P5414 四件礼物：四件拆两对 / 带件数背包

### 我的初始思路

先按价格降序，再 DFS + 回溯；随后回忆不起 0/1 背包，并主动提出“能否拆成两个二元组计算”。

### 判断

`[learning]`

### 可行模型 A：带件数的 0/1 背包

`dp[k][sum]`：能否恰好选 `k` 件，总价为 `sum`。

每件物品只能使用一次，因此 `k` 和 `sum` 需要倒序更新。

### 可行模型 B：拆成两个二元组

将最终四个编号排序为 `i<j<k<l`，拆成：

`(i,j) + (k,l)`

枚举后两件 `(k,l)`，前两件从编号前缀中查询“不超过剩余预算的最大 pair sum”。这能天然避免两对重复使用同一件礼物。

### 暴露问题

面对固定选 4 件时，先想到完整 DFS，而没有优先考虑“拆半 / pair sum / 带件数 DP”。

## 14. P5415 还原流量走法：欧拉路径 / Hierholzer

### 我的初始思路

认为做一个字符串到数字的映射表，然后遍历图即可；此前未学过 Hierholzer。

### 判断

`[weak]`

### 正确思路

题目关键词：**每条边恰好使用一次**。

这是欧拉路径，不是普通 BFS/DFS。Hierholzer 的核心：

1. 沿未使用边继续走；
2. 一条边走过就删除/标记；
3. 当前节点没有剩余出边时，才把节点加入 `path`；
4. 最后 reverse。

为了字典序最小，每个节点的出边使用字符串小根堆。

### 延伸辨析

- 每条边恰好一次 → 欧拉路径 / Hierholzer。
- 每个节点恰好一次 → Hamiltonian Path；小规模时常用 `dp[mask][u]` 状压 DP。
- `mask` 本质就是用整数二进制位记录整套访问节点状态。

## 15. C++ / STL 实现问题

### 本轮出现的典型错误

- `sort(v.end(), v.begin())`：把“降序”错误理解成反向传区间，应使用比较器 `greater<>()`。
- `sort(first,last)` 的区间是 `[first,last)`。
- 自定义比较器必须是严格比较 `<` / `>`，不能用 `<=` / `>=`。
- `priority_queue<T,Container,Compare>` 参数语义还需要继续熟悉。
- 一维/二维 vector 下标层级混淆。
- `__int128` 不能直接 `cout`，需要手动转十进制字符串。
- 递归中引用修改状态后必须恢复，否则污染外层搜索。

### 判断

`[weak]`

这部分不是算法模型问题，而是直接影响笔试通过率的实现可靠性问题，需要单独训练。

# 本轮重复薄弱点

## 1. `[weak]` 算法模式识别：不会先从“暴力做什么”抽象出经典结构

重复出现：护栏补强、驿站补给、鲤鱼离岛、区间上下界、基站干扰、四件礼物、欧拉路径。

典型表现：

- 看到“最小值”就想到堆；
- 看到图就容易想到拓扑；
- 看到四件组合就 DFS；
- 知道暴力，但不能继续追问“暴力重复计算了什么”。

训练优先级：最高。

## 2. `[weak]` 状态定义：状态里缺少会影响未来决策的信息

典型：驿站补给只保存 `dp[station]` 的单一电量；最长匀差脉冲中 `count` 含义变化；麻将递归修改状态未恢复。

训练问题：写代码前必须先回答“两个历史情况如果当前位置一样，未来行为是否一定一样？如果不一样，还缺什么状态？”

## 3. `[weak]` C++ 实现稳定性

反复出现：下标越界、容器复制时机、`sort` 参数、输入表达式、栈清空条件、递归恢复、一维二维访问混淆。

训练优先级：高。建议把“算法正确但实现错误”单独统计，不要和“完全不会算法”混为一类。
