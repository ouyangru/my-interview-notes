## 我的初始思路

我先尝试按类型建立：

```cpp
unordered_map<int, vector<int>> mMap;
```

同时保存 `(d,t)`，并准备设计：

```cpp
vector<vector<int>> dp(K+1, vector<int>(K+1, -1));
```

大致想让 DP 同时记录“选了多少个”和“用了多少种类型”，但写到转移时卡住，因为只知道“已有 j 种”并不知道“具体是哪 j 种”，所以无法判断当前 t 是新类型还是旧类型。

这次卡点不是单纯“不会写转移”，而是状态本身丢失了会影响未来决策的信息。

## 复盘判断

这题更适合“排序 + 贪心交换”，普通的 `dp[i][j]` 不适合直接描述，因为未来是否增加种类数取决于已选类型集合的具体身份。

如果强行把集合塞进 DP，需要类似 bitmask；当类型数较大时状态不可行。因此应该转而观察目标函数的结构：

```text
基础收益 sum(d) + 多样性奖励 x^2
```

先把基础收益做到最大，再研究为了增加一种类型，如何用最小代价交换。

## 正确模型：基础最优解 + 最小代价交换

### 第一步：忽略种类奖励

如果暂时忽略 `x^2`，恰好选 K 个时，最优方案就是按 d 从大到小排序，直接取前 K 个。

这给出了一个明确的“基础最优解”。

### 第二步：分析“种类数 +1”需要付出的代价

假设当前已经有 x 种类型，要变成 x+1 种，必须加入一个当前没出现过的新类型，同时删除一个已选元素以保持总数仍为 K。

被删除的元素必须来自“重复类型中的额外元素”。如果删掉某个类型唯一的元素，就会失去一个旧类型，种类数不会增加。

### 第三步：让交换损失最小

因此每次增加新类型时：

1. 新加入的候选应尽量大；
2. 被删除的重复元素应尽量小。

由于所有候选已经按 d 降序扫描，后面第一次遇到的“未出现类型”就是当前最优的新类型候选；已选重复项则用小根堆维护，优先删掉其中最小的 d。

每次交换后重新计算：

```cpp
ans = max(ans, sum + 1LL * cnt * cnt);
```

不能假设种类越多答案一定越大，因为增加种类可能损失过多基础收益。

## 标准实现

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int N, K;
    cin >> N >> K;

    vector<pair<long long, int>> a(N);
    for (int i = 0; i < N; ++i) {
        int t;
        long long d;
        cin >> t >> d;
        a[i] = {d, t};
    }

    sort(a.begin(), a.end(), [](const auto& x, const auto& y) {
        return x.first > y.first;
    });

    unordered_set<int> seen;
    priority_queue<long long, vector<long long>, greater<long long>> duplicate;

    long long sum = 0;

    for (int i = 0; i < K; ++i) {
        auto [d, t] = a[i];
        sum += d;

        if (seen.count(t)) {
            duplicate.push(d);
        } else {
            seen.insert(t);
        }
    }

    long long cnt = seen.size();
    long long ans = sum + cnt * cnt;

    for (int i = K; i < N; ++i) {
        auto [d, t] = a[i];

        if (seen.count(t)) {
            continue;
        }

        if (duplicate.empty()) {
            break;
        }

        sum -= duplicate.top();
        duplicate.pop();

        sum += d;
        seen.insert(t);

        cnt = seen.size();
        ans = max(ans, sum + cnt * cnt);
    }

    cout << ans << '\n';
}
```

## 为什么这次 DP 会卡住

这次值得记住的判断不是“这题要用堆”，而是：

> 如果一个 DP 状态只记录“有多少类”，但下一步转移需要知道“具体有哪些类”，说明状态信息不足。

此时有三种方向：

1. 类型数很小：把集合放进 bitmask；
2. 存在可压缩的等价信息：重新设计状态；
3. 集合很大但目标有排序/交换结构：检查是否能用贪心。

本题属于第三种。

## 我的思路模板

以后遇到“固定选 K 个 + 基础收益 + 额外奖励”时，先问：

1. **忽略额外奖励时，基础最优解是什么？**
2. **让奖励提升一级，需要进行什么交换？**
3. **这个交换怎样做到损失最小 / 收益最大？**

如果这三个问题都能局部证明，就优先检查贪心交换，而不是马上上二维 DP。

## 当前代码中的实现问题

除了算法模型，本次代码还暴露了几个 C++ 实现问题：

### 1. 输入循环多读一次

写成了：

```cpp
for (int i = 0; i <= N; i++)
```

应为：

```cpp
for (int i = 0; i < N; i++)
```

### 2. unordered_map 不能直接 sort

```cpp
sort(mMap.begin(), mMap.end(), ...);
```

`unordered_map` 没有随机访问迭代器，也不存在可直接排序的内部顺序；真正应该排序的是保存候选项的 `vector`。

### 3. count1 未初始化

```cpp
int count1;
```

随后直接参与判断属于未定义行为，应至少初始化为 0。

### 4. 不要预设最终一定有 K 个不同类型

```cpp
int result = K * K;
```

这种写法相当于先假定最终类型数一定为 K，但最优解可能保留更少类型以换取更大的 `sum(d)`，因此必须在每个可行种类数下比较总答案。
