## 实习经历一：小鹏汽车 TBox / 自动化测试 / 中间件

### 简历事实

时间：2026.07 - 至今。

主要内容：

- 参与 TBox 自动化测试台架 TBench 搭建，基于 Python、Shell 编写内核及板级测试用例，完善测试结果判定与异常日志采集流程。
- 完成 TBench 与飞书机器人的接入，实现测试任务下发、执行状态通知、日志回传及结果反馈的自动化闭环。
- 针对五百余万条 TBox 状态报告查询瓶颈，通过 EXPLAIN 定位全表扫描、临时表及文件排序问题，拆分终端维度数据，重构 Django ORM 查询链路并优化索引，将核心图表接口加载时间由约 60 秒降低至 1～2 秒。
- 参与车载通信中间件开发与维护，完成通信功能适配及运行异常定位，熟悉 DDS Topic 发布订阅、请求响应、共享内存 IPC、跨节点通信及 DDS-SOME/IP 适配等机制。

### 模拟面试默认追问

3. 8676 日志缺失问题的现象、根因、修复方案和验证方式是什么？为什么这是竞态问题？
4. 健康系统 500 万数据查询慢，EXPLAIN 里具体看到什么？为什么拆分终端维度和加索引能把 60 秒变成 1～2 秒？
5. SQLite 迁移到 MySQL 时，外键、缺列、COUNT 为 0、导入权限不足分别怎么排查？
6. DDS Topic、请求响应、共享内存 IPC、跨节点通信、DDS-SOME/IP 适配分别解决什么问题？

### 风险点

这段经历容易被问到“你到底是做测试平台，还是做业务开发”，回答时要先承认 TBench 是测试台架，但落点放在嵌入式 Linux、板端测试、日志链路、通信中间件和工程问题定位，不要把它讲成单纯前后端工具。

## 项目一：全志 V853 视频采集与流媒体服务

### 简历事实

时间：2025.09 - 2026.04。角色：项目负责人。

主要内容：

- 基于 V4L2 与 mmap 实现摄像头数据采集，采用独立采集线程共享视频源，通过 StreamManager 完成采集、封装与网络发送解耦。
- 设计控制面与数据面分离的流媒体架构，以 HTTP API 提供推流启停、协议选择及状态查询，以 RTSP 和 HTTP-FLV 承载实时视频数据传输。
- 实现 FLV Header、Tag 及 H.264 视频数据封装与发送，接入 GStreamer、gst-rtsp-server 提供 RTSP 标准流输出，同时支持 MJPEG over HTTP 实时预览。
- 基于 epoll、非阻塞 Socket 和线程池构建多客户端服务，通过 EPOLLOUT 驱动视频发送，并结合独立发送队列、队列上限和慢客户端丢帧策略避免线程占用及数据积压。

### 模拟面试默认追问

1. V4L2 从打开设备、申请 buffer、mmap、QBUF、STREAMON、DQBUF 到重新 QBUF 的流程是什么？
2. mmap 在 V4L2 采集中减少了什么拷贝？它是不是完全零拷贝？
3. 为什么要有独立采集线程和 StreamManager？采集、封装、发送耦合在一起会有什么问题？
4. 控制面和数据面怎么分离？HTTP API 控制推流和 RTSP / HTTP-FLV 传输视频为什么要分开？
5. FLV Header、Tag、H.264 NALU、RTSP、RTP、MJPEG over HTTP 分别在链路中处于什么位置？
6. epoll + 非阻塞 Socket + EPOLLOUT 在多客户端发送里怎么工作？什么时候注册写事件？什么时候取消？
7. 慢客户端为什么会拖垮系统？独立队列、队列上限、丢旧帧、断开连接、降帧率/降码率之间如何取舍？

### 风险点

这段项目是你最适合展开工程设计的项目，但不要一上来堆名词；面试官问“为什么这么设计”时，要按“问题 → 设计 → trade-off → 极端情况”讲完整。

## 项目二：基于 x86 架构的类 Linux 操作系统

### 简历事实

时间：2025.11 - 2026.02。角色：项目负责人。

主要内容：

- 实现 Bootloader 与 Loader，完成从实模式到 32 位保护模式的切换，并配置 GDT、IDT 及中断控制器。
- 实现基于位图的物理内存分配器与分页机制，分别构建内核和用户进程虚拟地址空间，完成地址空间隔离。
- 设计 PCB 与基于优先级的时间片轮转调度机制，实现 fork、exec、exit、wait 等进程控制及用户态与内核态切换。
- 构建 VFS 抽象层并实现 FAT16 文件系统、系统调用及 ELF 程序加载，开发支持内置命令和外部程序执行的 Shell。
- 简历中还列出实现系统调用机制、移植 Newlib 标准 C 库和开发 Shell。

### 模拟面试默认追问

1. Bootloader 和 Loader 分别做什么？为什么要从实模式切到保护模式？GDT / IDT / 中断控制器分别解决什么问题？
2. 物理内存位图分配器怎么管理页？虚拟地址空间怎么映射到物理页？内核空间和用户空间如何隔离？
3. PCB 里保存哪些信息？进程切换时保存/恢复哪些上下文？时间片轮转和优先级怎么结合？
4. fork、exec、exit、wait 的语义是什么？fork 后父子进程地址空间如何处理？有没有 COW？
5. 系统调用从用户态陷入内核态的流程是什么？参数怎么传？返回值怎么回到用户态？
6. VFS 为什么要存在？FAT16 文件系统和 VFS 的接口边界是什么？ELF 加载要解析哪些段？
7. 哪些是自己实现的，哪些是参考教程或移植的？简历措辞必须和真实 ownership 对齐。

### 风险点

这个项目容易被追问真实实现细节，尤其是调度、页表、fork、系统调用和 ELF 加载；回答时要严格区分“我实现过 / 我理解过 / 我参考过”，不要把不稳定的细节主动抬得太高。

## 默认模拟面试策略

当用户只说“模拟面试”但没有给岗位时，默认按“嵌入式软件开发工程师 / Linux 系统软件 / 车载 TBox”方向开始；如果用户给了 JD，则优先按 JD 筛选本页经历。

提问优先级建议：

1. 先用简历主线开场，问自我介绍和最熟悉项目。
2. 再抓小鹏或经纬恒润 TBox 实习，追问车云通信链路、Linux-MCU 分工、异常定位和测试闭环。
3. 然后追问 V853，因为这是最能体现 Linux、网络编程和工程设计的项目。
4. 再抽问 OS 项目，但注意 ownership 风险，不要默认把所有底层机制都判定为已经掌握。
5. 最后结合 STATUS.md 的 weak / wrong / learning 项进行针对性补刀。
