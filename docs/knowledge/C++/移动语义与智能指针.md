# 移动语义与智能指针

- 状态：`[weak] [wrong] [interview]`
- 来源：2026-06-22 影石相机 UI 开发实习一面；后续复盘讨论；2026-09-14 再次复习

## 我的理解

拷贝构造和移动构造都属于“用已有对象创建新对象”，区别在于资源怎么处理。拷贝构造是复制一份资源，原对象和新对象之后都能独立使用；移动构造是从一个临时对象或即将不用的对象那里接管资源，避免昂贵深拷贝，并把原对象置成安全可析构的空状态。

目前更适合从“指针和资源”建立直觉，而不是先背右值引用语法：如果 `p` 指向一块堆内存，那么浅拷贝只是把 `p` 中保存的地址复制给另一个指针，两个指针仍然指向同一块资源；深拷贝则重新申请一块新的内存，再把原资源内容复制过去；移动不是再复制一份资源，而是把原来的资源地址交给新对象管理，并把旧对象里的指针清空。可以先把三者记成：**浅拷贝 = 复制地址，深拷贝 = 复制资源，移动 = 转移资源所有权。**

面试官让我“从构造和拷贝的角度考虑”时，核心不是只背语法，而是解释对象生命周期和资源所有权。`unique_ptr` 不能拷贝，是因为它表达独占所有权；如果允许拷贝，就会有两个指针都认为自己拥有同一块资源，最后可能重复释放。它可以移动，因为移动是所有权转移，不是复制出第二个拥有者。

## 易错点

- `[wrong]` 右值引用不能解释成“临时对象不直接销毁，然后绑定到新对象”。关键是移动语义和资源转移。
- `[wrong]` `std::move` 本身不移动资源，它只是把表达式转换成右值，真正的移动发生在移动构造或移动赋值里。
- `[weak]` 目前对“浅拷贝为什么会导致 double free、深拷贝为什么需要重新申请内存、移动为什么只转移指针”这一层直觉仍不稳定，不能直接跳到 `T&&`、Rule of Five 或控制块。
- `[weak]` `unique_ptr` 底层不要说引用计数。它通常就是很薄的 RAII 包装，内部主要持有裸指针，析构时释放，禁止拷贝，允许移动。
- `[learning]` `shared_ptr` 可以拷贝，但拷贝的不是底层对象本身，而是共享控制块并增加强引用计数。
- `[weak]` `shared_ptr` 引用计数通常放在控制块里，控制块一般在堆上，里面还有弱引用计数、删除器等信息。

## 当前最小理解模型

```cpp
int* p = new int(10);
int* q = p;
```

这里 `q = p` 只复制了地址，因此 `p` 和 `q` 指向同一块堆内存。如果两边都 `delete`，就会重复释放同一块资源，这就是理解浅拷贝问题的起点。

深拷贝对应的是：

```cpp
int* q = new int(*p);
```

此时 `p` 和 `q` 指向两块不同的内存，只是里面保存的值相同。

移动可以先粗略理解为：

```cpp
q = p;
p = nullptr;
```

它不是标准移动构造的完整实现，但能帮助理解“资源没有复制，只是换了拥有者”。后续再把这个模型映射到类的移动构造、`std::move` 和 `unique_ptr`。

## 面试推荐回答

如果被问“右值引用是什么”，可以回答：

> 右值引用是 C++11 引入的机制，形式是 `T&&`，核心作用是支持移动语义和完美转发。我面试里最应该先讲移动语义：如果一个对象内部持有堆内存、文件描述符这类资源，而这个对象是临时对象或之后不再使用，就没必要深拷贝资源，可以通过移动构造把资源所有权转移给新对象，再把原对象置成空但可析构的状态。`std::move` 本身不移动资源，它只是把对象转换成右值表达式，真正移动发生在移动构造或移动赋值函数里。

如果被问“unique_ptr 的底层原理”，可以回答：

> `unique_ptr` 本质上是独占所有权的智能指针，底层可以理解成一个 RAII 包装，内部主要保存一个裸指针，析构时自动释放它管理的资源。它禁止拷贝构造和拷贝赋值，因为如果两个 `unique_ptr` 同时拥有同一块资源，就会出现重复释放；但它支持移动构造和移动赋值，通过 `std::move` 把资源所有权转移给另一个 `unique_ptr`，原来的指针变成空。相比 `shared_ptr`，`unique_ptr` 没有控制块和引用计数，开销更低，也更清楚地表达资源归属。

如果被问“shared_ptr 引用计数在哪里”，可以回答：

> `shared_ptr` 通常由两部分组成：一个是 `shared_ptr` 对象本身，里面保存资源指针和控制块指针；另一个是控制块，通常在堆上，里面保存强引用计数、弱引用计数、删除器等信息。多个 `shared_ptr` 指向同一资源时共享同一个控制块，强引用计数归零时释放被管理对象，弱引用计数也归零后控制块才释放。
