# 结构体指针步长与内存对齐

> 状态：`[weak]`  
> 标签：`[interview]`
> 最近复习：2026-09-24

!!! question "面试问题"
    一个结构体指针 `p` 执行 `p + 1` 后，地址究竟移动多少？这个结论和结构体内存对齐有什么关系？

## 先形成条件反射

对任意完整对象类型 `T`：

```cpp
T* p = /* 指向 T 数组中的某个元素 */;
T* q = p + 1;
```

`q` 指向下一个 `T` 对象，数值地址增加 `sizeof(T)` 个字节。一般式是：

\[
\operatorname{addr}(p+n)=\operatorname{addr}(p)+n\times\operatorname{sizeof}(T)
\]

因此如果 `p` 是 `struct Node*`，`p + 1` 的步长就是 `sizeof(struct Node)`，不是 1 字节，也不是“移动到当前结构体末尾”这种模糊说法。

要注意，C/C++ 标准只在同一数组对象内部（以及允许计算尾后指针的位置）定义这种指针运算；不要把任意地址强转成结构体指针后随意相加。

## 为什么 `sizeof(struct)` 已经包含 padding

结构体数组要求任意相邻两个元素的每个成员都满足自己的对齐要求。因此编译器不仅可能在成员之间插入 padding，还可能在结构体末尾加入尾部 padding，使下一个数组元素的起始地址仍满足结构体的对齐要求。

例如在常见的 `int` 为 4 字节且按 4 字节对齐的 ABI 下：

```cpp
struct S {
    char c;
    int  x;
};
```

典型布局是：

```text
offset 0       : c
offset 1..3    : padding
offset 4..7    : x
sizeof(S) == 8
```

所以 `S* p; p + 1` 典型移动 8 字节。这里必须说“在该 ABI / 编译选项下通常为 8”，不能把具体大小脱离平台说成语言标准的固定答案。

## 计算结构体大小的稳定步骤

1. 按成员声明顺序放置成员；
2. 每个成员的起始偏移满足该成员的有效对齐要求；
3. 结构体总大小补齐到结构体有效对齐量的整数倍；
4. `#pragma pack`、编译器属性和 ABI 可能改变有效对齐量；
5. 用 `offsetof` 和 `sizeof` 在目标平台验证，不凭感觉猜 16/32 位倍数。

## 本场面试为什么仍算薄弱

面试官问“结构体指针 `p + 1` 会偏移多少”时，我先说“直接变到结构体末尾”，在继续追问“加了多少”后才回答“结构体大小”。结论最后说对了，但没有第一时间说出类型化指针运算规则，也没有把它和 `sizeof(struct)` 中的 padding 连接起来。

题面后续似乎要求由某个结构体大小或地址差推出“完全平方数”等特征，但录音没有保留屏幕上的完整结构体定义、表达式和选项，转写也存在大量缺字。因此本次只记录能够确认的 `p + 1` 规则；不能根据残缺录音补造题目或断言“完全平方数”结论。

!!! warning "我容易答错的地方"
    - `[weak]` 先猜 16 位、32 位或“对齐”，没有先写 `p + 1 = p + sizeof(*p)` 的地址步长。
    - `[weak]` 把“指向下一个结构体对象”说成“到当前结构体末尾”，没有说明它是数组语义下的下一个元素起始地址。
    - `[weak]` 需要主动区分：只有把指针转换为字节指针后，`(char*)p + 1` 才是移动 1 字节；本场没有证据表明我明确坚持过“结构体指针只移动 1 字节”的错误结论。
    - `[learning]` 知道 padding 会影响 `sizeof`，但遇到完整题目时还需要稳定计算成员偏移和尾部 padding。

## 推荐口头回答

> `p + 1` 的逻辑单位是一个 `*p` 对象，所以如果 `p` 的类型是 `struct S*`，地址会增加 `sizeof(struct S)` 字节。这个 `sizeof` 已经包含成员之间和结构体末尾为了对齐产生的 padding，正因为这样，结构体数组中下一个元素的起始地址仍然满足对齐要求。具体 `sizeof` 取多少要看成员顺序、ABI 和 pack 设置，不能只凭 32 位或 64 位猜。
