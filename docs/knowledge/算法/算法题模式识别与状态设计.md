## 一、复杂度先行：先用数据范围否掉错误方向

### 我的易错点

看到题意就直接模拟。例如护栏题想每次施工都从小根堆里找最低点，但 `T` 最大到 `1e9`。

### 固定检查

- `n≈1e5`：`O(n^2)` 基本危险。
- `n≈2e5`：优先考虑 `O(n)` / `O(n log n)`。
- 操作次数本身可到 `1e9`：不能逐次模拟。
- `n<=20`：可以考虑 `2^n` 状压。
- 某个数值上限只有 `1e4`：可能适合背包/按值域 DP/bitset。

## 二、模式触发器

### 1. 最大化最小值 / 最小化最大值

先问：

> 如果我猜一个答案 X，能否快速判断 X 是否可行？

若可行且具有单调性，优先考虑 **二分答案**。

典型：护栏补强。

`最大化最小值 + 区间批量加 → 二分答案 + 差分/扫描`

---

### 2. 左右最近第一个更大/更小

关键词：

- 左边最近严格更大；
- 右边第一个不小于；
- 每个位置向两边能扩到哪里，直到遇到阻挡。

优先想到 **单调栈**。

本轮重复暴露：P5315、P5413。

我需要形成的反射：

> “每个元素都向左/右反复找第一个满足大小关系的位置” = 暴力有大量重复比较 = 单调栈。

严格大小要特别注意弹栈条件：题目要求 `>` 时，相等元素通常不能被当作“更大”，但可能需要作为阻挡保留。

---

### 3. 无权最短路 / 一层层扩散

`上下左右每步代价相同 / 最少走几步 / 第几层到达 → BFS`

不要因为“是图”就想到拓扑排序。

拓扑排序的触发词应该是：

`依赖 / 前置条件 / DAG / 入度为0 / 合法执行顺序`

---

### 4. 有权非负最短路

`边权不同 + 求最短累计代价 → Dijkstra`

本质只有两步：

1. 小根堆取当前 `dist` 最小的状态；
2. 松弛邻居：`dist[v] = min(dist[v], dist[u]+w)`。

BFS 是“按层数扩散”，Dijkstra 是“按累计花费扩散”。

---

### 5. 同一个位置，不同资源会影响未来

如果到同一个节点时，剩余电量/次数/钥匙/优惠券状态不同，会导致后续可走路径或代价不同，那么 `dp[node]` 不够。

要把资源加入状态：

`state = (node, resource)`

然后在扩展状态图上跑 BFS / Dijkstra。

典型：驿站补给。

判断状态是否充分的自问：

> 两个历史情况如果当前“位置”相同，它们未来的所有选择和代价是否完全一样？

如果不是，状态还缺信息。

---

### 6. 每条边恰好走一次

`每条边恰好使用一次 → 欧拉路径 / Hierholzer`

Hierholzer 的关键不是普通 DFS 的“访问节点”，而是“消耗边”：

- 走过的边立即删除/标记；
- 当前节点没有剩余边时才加入答案；
- 最后 reverse。

如果要求字典序最小，可让每个节点的出边按字典序取最小。

不要和下面混淆：

- 每个节点恰好访问一次 → Hamiltonian Path；
- 小规模 Hamiltonian 常见 `dp[mask][u]`。

---

### 7. 访问节点集合本身会影响下一步

当“当前在哪”还不够，必须知道之前访问了哪些点：

`dp[mask][u]`

`mask` 就是一个整数位图：第 `i` 位表示节点 `i` 是否已访问。

适用规模通常很小，因为共有 `2^n` 个访问集合。

---

### 8. 最短路有多条，还要按次级指标选最优

先让最短路算法只解决第一优先级。

例如网格中：

1. BFS 得到 `dist`；
2. 只保留 `dist[next]=dist[cur]+1` 的边；
3. 这些边构成分层 DAG；
4. 在 DAG 上 DP 比较额外指标，并记录 parent。

模式：

`最短路 + 同长度路径二次比较 → 最短路子图/DAG + DP`

---

### 9. 大量区间覆盖，每个位置求当前覆盖集合 min/max

暴力：对每个区间逐点更新。

如果区间和位置都是 `1e5~2e5`，基本不可行。

可改成：

- 从左到右扫描位置；
- 在区间左端点把操作加入堆；
- 用右端点删除过期操作；
- 求 min 用小根堆，求 max 用大根堆。

典型：P5316。

注意：差分适合可加减的区间增量，不是所有区间操作都能差分。

---

### 10. 恰好选 K 件，总和受小上限约束

考虑：

`dp[k][sum]`

表示能否恰好选 `k` 件组成 `sum`。

0/1 背包中，同一物品只能用一次，因此容量通常倒序更新。

如果固定只选四件，也可以按编号排序后拆成：

`(i,j) + (k,l), i<j<k<l`

再做 pair sum / meet-in-the-middle 风格查询。

典型：四件礼物。

---

### 11. Σ w_i |x_i-X|

最优 `X` 是 **加权中位数**。

按坐标排序后，找第一个满足：

`prefixWeight * 2 >= totalWeight`

的坐标即可。

二维曼哈顿距离可独立拆成 x、y 两个一维问题。

---

### 12. 网格 DP 只依赖上方和左方

二维 `dp[i][j]` 如果只依赖：

- `(i-1,j)`；
- `(i,j-1)`；

通常可以压缩到一维 `dp[j]`：

- 更新前的 `dp[j]` 是“上方”；
- 已更新的 `dp[j-1]` 是“左侧”。

---

### 13. 两变量关系方程

若每条方程只连接两个变量，不要第一反应就上通用矩阵消元。

如果关系可写成：

`x_v = ±x_u + c`

可建图后 BFS/DFS 传播相对关系。每个连通块选一个独立参数 `t`，节点表示成：

`x_i = sign_i * t + bias_i`

环/重复路径用于检查矛盾或确定 `t`。

## 三、实现层反复错误

### 1. 状态变量含义不固定

例如 `count` 一会表示差值个数，一会表示原数组长度。

改法：循环前给每个变量写一句定义。

### 2. 递归修改引用后不恢复

回溯固定结构：

```cpp
修改状态;
if (dfs(...)) {
    恢复状态;
    return true;
}
恢复状态;
```

或者直接传值/复制下一状态，牺牲一点性能换实现简单。

### 3. 容器复制时机

`vector<vector<int>> mOrder={Wan,Tong,Tiao};` 是复制，不是引用。若在读牌前构造，后面修改原 vector 不会同步。

### 4. STL 区间与比较器

- `sort(v.begin(), v.end())`：升序；
- 降序用 `greater<>()` 或 lambda；
- 不能写 `sort(v.end(),v.begin())`；
- STL 区间通常是 `[first,last)`；
- `sort` 比较器要严格 `<` / `>`，不要 `<=` / `>=`。

### 5. 一维/二维状态层级混淆

`vector<int> dp` 只能访问 `dp[j]`；滚动数组已经把二维状态压掉后，不能再写 `dp[i][j]`。

### 6. 边界检查

涉及 `i+1/i+2`、`size`、栈顶时，先确认：

- 是否越界；
- 栈是否为空；
- 哨兵是否真的覆盖数据范围。

## 十四、相邻元素反复合并：先转化为原序列连续分段

### 本次笔试暴露

面对“任选连续子段，用元素和替换，操作任意次”的 01 序列计数题，我没有先定义最终状态，而是卡在“有很多个 1 怎么办”“连续三个 1 怎么办”“两个 1 中间没有零为什么仍贡献 2”。

核心缺口不是不会乘法，而是没有先完成两步抽象：

1. 反复相邻合并等价于对原序列选择一组连续分段；
2. 统计对象是不同的段和序列，不是不同分割位置。

### 固定触发规则

看到下面的操作时：

- 只能合并相邻元素；
- 合并结果仍能继续参与操作；
- 元素顺序不变；
- 问所有可能最终状态；

先问：

> 最终每个元素是否对应原数组的一个连续段？

如果是，就停止模拟操作顺序，直接研究原数组的连续分段及其去重结果。

### 01 序列为什么能按间隙相乘

最终正整数序列描述了所有 1 被分成哪些连续组。每对相邻 1 之间：

- 不切开：贡献 1 种；
- 切开：若中间有 z 个零，最终可以保留 0 到 z 个零元素，贡献 z+1 种。

所以内部零间隙贡献 z+2。连续的 11 对应 z=0，仍有“不切得到 2”和“切开得到 1,1”两种。

如果至少有一个 1：

ans = (首部零数+1) × (尾部零数+1) × Π(内部零数+2)

如果全是零，答案为 n。

### 我的易错点

- 把“没有零”误解成“没有选择”，忽略了两个 1 本身仍可切开。
- 只理解一对 1，没有把多个 1 看成多条相互独立的边界决策。
- 容易数切割方式，而题目实际要求对最终数值序列去重。
- 从例子得到因子后，没有先证明不同间隙的选择为何能够使用乘法原理。

### 做题检查

1. 每次操作是否只会把原区间合并，绝不会打乱顺序？
2. 最终对象能否唯一还原“哪些相邻 1 被切开”和“每个间隙留下几个零元素”？
3. 多种原始切法是否可能产生同一个最终数值序列？
4. 全零、全一、只有一个 1、首尾有零是否分别覆盖？
5. 数据总量接近 200000 时，最终公式是否能一遍扫描计算？

## 十五、小常数空间：先枚举合法结构，再考虑复杂索引

> 来源：[2026-09-18 算法笔试复盘](../../written-tests/2026-09-18-算法笔试复盘.md) `[written-test]`

### 本次暴露

9×9 棋盘判断矩形封闭结构时，我先维护 row / lie 去筛候选边，再检查四条边。方向并非完全错误，但对只有 9×9 的题目属于明显过度设计，同时增加了循环变量、边界和坐标方向出错的机会。

更稳的顺序应该是先算完整候选规模。轴对齐矩形只有 C(9,2)×C(9,2)=1296 个，直接枚举 x1<x2、y1<y2 并检查四边即可。

### 固定触发规则

看到“小网格 / 小值域 / 固定常数范围 + 判断某种几何或组合结构”时，先问：

1. 所有合法结构总数到底有多少？
2. 直接枚举每个结构并验证是否已经足够快？
3. 额外索引或剪枝是否真的减少了必要复杂度，还是只增加实现状态？

如果完整枚举只有几千、几万甚至更少，优先选择最直接的版本，尤其在笔试限时环境中。

### 本次实现错误一起记

- `for (int j = ...; ...; i++)`：循环变量与递增变量不一致，直接导致死循环 TLE；
- `!a[x][y] && y < n`：数组访问发生在边界判断之前，可能越界；
- `< maxGrowLength` / `<= maxGrowLength`：需要先根据“初始格是否计入长度”明确语义；
- 非 void 函数末尾漏 `return false`；
- Up/Down、Left/Right 的坐标变化必须按题目坐标系确认。

### 提交前 20 秒机械检查

1. 每个 for 的初始化、条件、递增是不是同一个变量；
2. 所有数组访问前是否先检查上下界；
3. `<` / `<=` 有没有 off-by-one；
4. 所有返回路径是否完整；
5. 坐标方向、行列含义是否从头到尾一致。

这类错误已经不是单次粗心，应继续归入“C++ 实现稳定性”重复薄弱点。
### 与原有 LeetCode 知识的对应

这次“如果要求被围住的空白区域本身是矩形”的变体，可以直接复用原知识库中网格 DFS / Flood Fill 的模型：

- [LeetCode 130 被围绕的区域](../../leetcode刷题.md)：最接近“封闭区域”这个概念。它从棋盘边界出发标记所有与外界连通的 `O`，剩下的才是真正被包围区域。若本题要求“封闭空白区域必须为矩形”，就在找到封闭连通块后继续统计 bounding box 和格子数。
- [LeetCode 200 岛屿数量](../../leetcode刷题.md)：对应“遍历整个网格，遇到未访问目标格就 DFS/BFS 吃掉一个连通块”的基本框架。矩形空腔变体中，每个空白连通块就是一次 DFS/BFS。
- [LeetCode 733 图像渲染](../../leetcode刷题.md)：对应从一个起点向上下左右扩展同类格子的 Flood Fill 模板，适合回练边界判断顺序和四方向遍历。

当前实际题意只是“四条边由树苗组成”时，不需要套 Flood Fill，直接枚举矩形四边更简单；上述三题只对应用户提出的“封闭空地本身为矩形”变体。

## 十六、固定选 K 个 + 附加奖励：先找基础最优解，再做最小代价交换

> 来源：[2026-09-19 贪心交换与种类奖励复盘](../../written-tests/2026-09-19-贪心交换与种类奖励复盘.md) `[written-test] [weak]`

### 本次暴露

面对“选 K 个物品，得分 = 基础收益总和 + 不同类型数量的额外奖励”时，我第一反应是设计 `dp[i][j]`，其中 j 表示已经用了多少种类型，但写转移时卡住。

真正的问题是：知道“有 j 种”并不足以判断下一个类型 t 是否已经出现过，未来转移依赖的是“具体有哪些类型”。这说明普通二维 DP 状态丢失了影响未来的信息。

### 固定触发规则

看到下面这种结构时：

```text
固定选择 K 个
目标 = 元素基础收益 + 与种类数/覆盖数/多样性有关的奖励
```

先不要马上设计 DP，依次问：

1. 忽略附加奖励时，基础最优解是什么？
2. 让奖励提升一级，需要交换什么元素？
3. 如何让这次交换的基础收益损失最小？

如果基础最优解可以通过排序得到，而“提升奖励”可以通过删除某类冗余元素、加入一个新候选实现，就重点检查交换型贪心。

### 本题的交换结构

- 忽略种类奖励：按 d 降序取前 K 个，得到最大 `sum(d)`；
- 想让种类数 +1：必须加入一个尚未出现的新类型；
- 为保持仍选 K 个：删除一个“重复类型中的额外元素”；
- 删除哪个：删 d 最小的重复元素，损失最小；
- 加哪个：按 d 降序继续扫描时，遇到的第一个未出现类型就是当前最优候选；
- 每次交换后都重新比较完整目标值，不能假设种类越多答案必然越优。

实现上通常是：

```text
排序 + seen 集合 + 重复元素小根堆 + 枚举交换次数
```

### 和 DP 状态设计的连接

如果 `dp[i][j]` 中 j 只记录“集合大小”，但下一步需要查询“某元素是否属于集合”，说明状态不充分。

此时的判断顺序：

- 集合规模很小：考虑 bitmask；
- 存在可压缩统计量：重新设计状态；
- 集合规模很大，但目标函数有排序和交换性质：考虑贪心。

### 我的易错点

- 看到“恰好选 K 个”就惯性想到背包/二维 DP，没有先拆目标函数；
- 发现状态不够后继续硬补变量，而不是停下来问“到底缺了哪部分历史信息”；
- 容易把优先队列当算法本身，其实堆只是维护“当前最小可删除重复项”的数据结构；
- 看懂交换过程不等于已经掌握，必须通过不同奖励函数、不同背景的换皮题独立识别。

### 做题前新增检查

在原有“暴力 / 复杂度 / 重复工作 / 触发词 / 状态定义”之后，再补一句：

> 如果状态需要记录一个很大的集合身份，能不能把问题改写成“基础最优解 + 交换”？

## 十七、恰好选 t 个且有间隔限制：状态要保存“选了几个 + 最后位置”

> 来源：[2026-09-20 状态设计、回溯与二分答案复盘](../../written-tests/2026-09-20-状态设计回溯与二分答案复盘.md) `[written-test] [weak]`

### 本次暴露

P5428 中一开始先设计 `Node{total_number,time}` 和 `dp[lim+1][n+1]`，但没有先定义状态语义。真正影响未来合法性的不是“当前连续放掉了几个”这一维本身，而是：已经选了几个，以及最后一个被选位置在哪里。

固定状态：

```text
dp[j][i] = 恰好选了 j 个，且第 j 个选中的位置是 i 时的最小代价
```

如果相邻选择之间最多能跳过 `lim` 个位置，那么上一个选择位置 `k` 必须满足：

```text
i-k-1 <= lim
```

因此：

```text
dp[j][i] = cost[i] + min(dp[j-1][k])
```

其中 `k` 位于长度最多 `lim+1` 的滑动窗口内。

### 固定触发规则

看到“恰好选 K 个 + 相邻选择位置有距离/间隔限制”时，优先问：

1. 已经选了几个是否影响最终合法性？
2. 最后一个选中位置是否决定下一步允许从哪里选？
3. 转移中的前驱集合是否是一个连续窗口？

如果答案分别是“是、是、是”，很可能是 `dp[选择数][最后位置] + 滑动窗口最值`。

### 进一步优化

若朴素转移每次都枚举窗口内所有 `k`，复杂度可能为 `O(K*n*lim)`。若窗口里只需要 min/max，可继续考虑单调队列，将一层优化到 `O(n)`。

### 我的易错点

- 状态还没定义就先写结构体；
- 把多个互斥历史状态压进同一个 Node，只保留一个结果；
- 没先检查转移中的 `min/max` 是否其实是滑动窗口查询。

## 十八、回溯里的“隐藏状态”：全局路径必须手动恢复

> 来源：[2026-09-20 状态设计、回溯与二分答案复盘](../../written-tests/2026-09-20-状态设计回溯与二分答案复盘.md) `[written-test] [weak]`

### 本次暴露

固定间隔选 `t` 个位置时，第一版用三层 `for`，实际上只能处理 `t==3`。当选择层数由输入决定时，更自然的模型是 DFS/回溯。

典型状态：

```text
start          下一次最早从哪里选
chosen.size()  已经选了几个
total          当前累计值
chosen         当前完整路径
```

如果 `chosen` 放在全局变量里，虽然函数参数变少了，但它仍然是递归状态的一部分，只是被“藏”起来了。

### 回溯固定模板

```cpp
chosen.push_back(i);   // 做选择
dfs(next, newTotal);   // 搜索包含这个选择的所有后续
chosen.pop_back();     // 撤销选择，恢复进入这一层之前的状态
```

### 固定判断

以后看到递归里的全局变量，先分两类：

- 当前路径/当前棋盘/当前频次等，会被不同分支修改：递归返回后通常必须恢复；
- `cnt`、最佳答案、前几组结果等全局统计：通常是所有分支共享累积，不需要回溯。

### 动态 K 与固定多层循环

如果题目要求“恰好选择 `t` 个”，而 `t` 是输入变量，就要警惕固定写三层、四层循环。固定层数只适用于 K 是编译时常量或题目明确固定的情况。

### 剪枝

若相邻选择至少隔 `g` 个位置，并且当前候选为 `i`、还需选 `remain` 个，那么最紧凑的最后一个位置为：

```text
i + (remain-1)*(g+1)
```

若它已经大于 `m`，当前及更大的 `i` 都不可能完成，可以直接 break。
