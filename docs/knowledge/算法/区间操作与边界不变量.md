# 区间操作与边界不变量

> 状态：`[weak] [written-test]`
>
> 来源：[2026-09-15 vivo 区间反色最大边界数复盘](../../written-tests/2026-09-15-vivo-区间反色最大边界数复盘.md)

## 我的理解

这类题最容易被题面的“整段修改”吓到，然后开始维护连续段、区间长度、颜色分布等复杂状态。更好的第一步不是研究整段怎么变，而是先问：**题目最终统计的量，在一次区间操作后到底有多少位置真的会受影响？**

vivo 这道题里，操作是把内部连续区间全部 `0/1` 反色，而目标是统计相邻字符不同的边界数。若两个相邻字符都在区间内部，它们会一起反色，因此“原来相同还是不同”完全不变。真正变化的只有区间左右两个端点对应的相邻关系。

所以应该把字符串转成边界数组：

```text
b[i] = (s[i] != s[i+1])
```

一次区间反色就从“修改一大段字符”变成了“翻转边界数组的两个点”。问题复杂度会直接下降一个层级。

## 固定模型

如果某类区间操作满足：

- 区间内所有元素同时做相同变换；
- 目标只依赖相邻元素之间的关系；
- 两个内部相邻元素同时变化后，其关系保持不变；

那么优先考虑把原数组转换成：

- 差分数组；
- 相邻异或数组；
- 边界数组；
- 相邻是否相等的 0/1 数组。

重点观察操作是否只影响区间端点。

## 易错点

我这次先按原字符串连续 `0` 段和 `1` 段分类，又进一步讨论段长的奇偶性。这个方向的问题不是完全错误，而是 **原始连续段不是操作下的不变量**：一次反色后，原来的段可能拆分、合并或者改变颜色，后续状态会越来越复杂。

以后如果发现自己正在为一次简单操作维护很多 run 的类型、长度和奇偶性，应立即反问：

> 有没有一种相邻关系表示，使区间内部根本不用维护？

## 本题结论

设当前已有边界数为 `boundary`，则非边界数量为：

```text
same = (n - 1) - boundary
```

每次操作最多把两个 `0` 边界位同时翻成 `1`，因此最多增加：

```text
2 * min(k, same / 2)
```

最终答案：

```text
boundary + 2 * min(k, same / 2)
```

复杂度 `O(n)`。

## 面试 / 笔试追问

1. 为什么区间内部的边界状态不会变化？
2. 为什么一次操作恰好只影响两个边界位？
3. 如果允许翻到字符串首尾，结论会怎么变化？
4. 如果要求“恰好执行 k 次”而不是“最多 k 次”，还是否能直接用同一公式？
5. 如果操作从“整体反色”改成“区间全部设为 0”，为什么边界数组方法不再能直接只看两个端点？
