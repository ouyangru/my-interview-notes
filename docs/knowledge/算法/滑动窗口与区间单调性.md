# 滑动窗口与区间单调性

> 来源：2026-09-15 算法练习 / 笔试题复盘
>
> 状态：`[weak] [learning]`

## 我的理解

这次真正卡住的不是 `deque`、`priority_queue` 或 `unordered_map` 的语法，而是没有先判断“连续区间是否合法”是否具有单调性。我一开始按每个 `left` 把 `right` 重新放到 `n`，再复制最大堆、最小堆和频次表，从右向左缩，这会把同一批状态重复计算很多次，复杂度接近 `O(n^2)`，而且整体复制容器本身也很重。

对于形如“统计满足若干限制的连续子数组数量”的题，应该先问：

> 当窗口 `[l,r]` 已经不合法时，继续扩大 `r` 是否只会更不合法；缩小窗口是否只会更容易合法？

如果答案是肯定的，就应该优先考虑双指针 / 滑动窗口，让 `left` 和 `right` 都只向右移动，而不是重新枚举二维区间。

## 固定模型：右端点扩张，左端点收缩

如果数组元素非负，约束例如：

- 区间和 `sum <= S`；
- 区间极差 `max - min <= D`；
- 不同元素个数 `kinds <= K`；

这三个量在扩大窗口时都只会“不变或变坏”：

- 非负数组下，区间和只会不减；
- 加入元素后 `max-min` 只会不减；
- 不同元素种类数只会不减。

因此可以维护一个最小合法左端点 `left`。每加入新的 `right`，如果窗口不合法，就不断右移 `left`，直到重新合法。

当 `[left,right]` 合法时，所有

```text
[left, right]
[left+1, right]
...
[right, right]
```

都合法，因此当前右端点贡献的合法子数组数是：

```text
right - left + 1
```

而不是整个窗口内部子数组总数 `len*(len+1)/2`。后者会把以后以 `left+1`、`left+2` 开头的区间提前算进去，导致重复计数。

## 三类状态分别怎么维护

### 1. 区间和

非负数组时只需要一个变量：

```cpp
sum += a[right];
while (sum > S) {
    sum -= a[left++];
}
```

### 2. 区间最大值 / 最小值

固定滑动窗口中的最大最小值不要优先用两个 `priority_queue`。堆可以做，但删除“已经滑出窗口的任意元素”比较麻烦，容易出现懒删除和状态复制。

更标准的是两个单调 `deque`：

- `maxQ` 对应值单调递减，队头是最大值；
- `minQ` 对应值单调递增，队头是最小值；
- 队列存下标，方便在 `left` 右移时删除过期元素。

每个下标最多进队、出队一次，因此总复杂度是 `O(n)`。

### 3. 不同元素个数

使用频次表：

```text
cnt[value] ++ / --
```

只有从 `0 -> 1` 时 `kinds++`，从 `1 -> 0` 时 `kinds--`。

## 本次实现错误

### 1. 每个 left 都重新搜索 right

现场代码中每轮都：

```text
right = n
复制两个 priority_queue
复制 unordered_map
然后从 n 向左缩
```

这样没有利用相邻窗口之间的大量重复状态，最坏接近 `O(n^2)`，并且容器复制进一步放大常数。

### 2. 合法区间计数重复

找到最大合法 `right` 后，写成：

```text
len * (len + 1) / 2
```

这是 `[left,right]` 内部所有子数组数量，会与后续左端点重复。固定左端点时只应该增加：

```text
right - left + 1
```

在“固定右端点”的标准滑窗写法中，同样是 `right-left+1`，含义是所有以 `right` 结尾的合法子数组。

### 3. 堆方向和过期条件容易写错

小根堆使用 `top()`，不是 `front()`；默认 `priority_queue` 是大根堆，小根堆需要 `greater<>`。复制时比较器必须完全相同，否则类型不同不能直接赋值。

本次还出现了 `min-max` 写反、右端点删除条件方向写反等问题，说明这类题继续堆叠两个 `priority_queue` 会增加实现负担。

## 有负数时为什么普通滑动窗口失效

这是本次最重要的边界条件。

若数组允许负数，`sum <= S` 不再具有窗口单调性。例如：

```text
a = [5, -10, 6], S = 3
```

窗口 `[5]` 时和为 `5 > 3`，但继续扩张得到 `[5,-10]` 后和变成 `-5`，重新合法。如果在 `[5]` 时就永久右移 `left`，后面会漏掉合法区间。

因此：

```text
全非负 + sum <= S  -> 普通滑动窗口
允许负数 + sum <= S -> 不能只靠双指针
```

## 负数场景：前缀和 + 有序统计结构

如果其他约束仍然单调，例如：

- `max-min <= D`；
- `kinds <= K`；

那么仍然可以用滑动窗口得到当前允许的左端点范围 `[L,r]`。对区间和单独处理。

定义前缀和：

```text
pre[0] = 0
pre[i+1] = pre[i] + a[i]
```

要求：

```text
sum(l..r) = pre[r+1] - pre[l] <= S
```

等价于：

```text
pre[l] >= pre[r+1] - S
```

所以对每个 `r`，问题变成：

> 在所有 `l ∈ [L,r]` 中，统计多少个 `pre[l] >= pre[r+1]-S`。

这可以通过“前缀和离散化 + Fenwick 树 / 其他有序计数结构”动态维护，整体做到 `O(n log n)`。

## 固定检查清单

以后遇到连续区间计数题，写代码前先问：

1. 固定一个右端点后，合法左端点是否形成连续区间？
2. 扩大窗口时，每个约束是单调变坏，还是可能先坏后好？
3. 如果有 `sum` 条件，数组里是否可能有负数？
4. 最大最小值是否应该用单调队列，而不是复制堆？
5. 当前 `right` 的贡献是不是 `right-left+1`，而不是再算一遍整个窗口内部子数组？
