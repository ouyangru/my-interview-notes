# 区间移动的边界贡献与接缝计数

> 状态：`[learning]`  
> 标签：`[algorithm]` / `[boundary-contribution]`  
> 最近复习：2026-09-12

!!! question "题目模型"
    给定数组，接缝定义为相邻元素不相等。选择非空连续片段 `[l,r]`，保持片段内部和剩余元素内部的相对顺序，把该片段整体移到数组最前面。求最少接缝数；有多解时输出字典序最小的 `(l,r)`。

### 我的理解

这题不需要真的构造移动后的数组。移动一个连续片段时，片段内部和剩余部分内部的相邻关系都不变，只有切口和重新拼接的位置可能改变，因此只计算边界贡献即可。

我一开始已经意识到：一次操作最多只能减少两个接缝。但为了避免“暴力”，先保存了所有等于数组第一个值的位置，希望直接找到让新接缝消失的端点，结果条件越分越复杂。问题在于 `a[r] == a[1]` 只控制其中一条新接缝，无法同时决定被删除的两条旧接缝和另一条新接缝。

更稳的判断顺序是：

1. 先看数据范围：`n <= 5000`，所有区间只有约 `n(n+1)/2` 个，`O(n^2)` 可以接受。
2. 枚举所有 `(l,r)`，但不要重建数组或重新遍历计算接缝。
3. 预处理原接缝数，每个区间只修改至多四条边，单次 `O(1)`。

设 `D(x,y) = [a[x] != a[y]]`，原接缝数为：

```text
S = sum(D(i, i+1)), 1 <= i < n
```

当 `l > 1` 时：

- 删除旧边 `(l-1,l)`；
- 若 `r < n`，删除旧边 `(r,r+1)`；
- 新增边 `(r,1)`；
- 若 `r < n`，新增边 `(l-1,r+1)`。

所以：

```text
cur = S
cur -= D(l-1, l)
if r < n:
    cur -= D(r, r+1)
cur += D(r, 1)
if r < n:
    cur += D(l-1, r+1)
```

`l == 1` 时移动的是原数组前缀，数组完全不变，接缝数仍为 `S`。

为了得到字典序最小的答案，按 `l` 从小到大、`r` 从 `l` 到 `n` 枚举，只在接缝数严格变小时更新答案；相等时保留先遇到的区间。

复杂度：时间 `O(n^2)`，空间 `O(n)`。

!!! warning "我容易答错的地方"
    - “枚举所有区间”不等于低效暴力。关键是每个区间用 `O(1)` 更新，而不是每次构造新数组形成 `O(n^3)`。
    - 不能只看 `a[r] == a[1]`；移动后的结果还取决于 `a[l-1]` 与 `a[r+1]`，以及被切断的旧边。
    - `l == 1` 必须单独理解：移动前缀到最前面不会改变数组。
    - `r == n` 时没有 `r+1`，只删除一条旧边并新增 `(n,1)`。
    - 字典序最小可以利用枚举顺序自然保证，不需要额外收集所有最优答案。

### 可迁移的解题模式

遇到“剪下一段再拼接、翻转一段、交换两段、改变少量连接关系”并且目标由相邻元素贡献组成时，优先检查：

- 操作后哪些内部关系保持不变？
- 真正变化的边界有几条？
- 能否先计算总贡献，再对每个候选操作做常数次加减？
- 数据范围是否允许枚举候选操作，而无需继续过早优化？

### 继续追问

- 如果目标改为相邻元素差的绝对值之和，四条边的增量公式如何写？
- 如果片段可以插入任意位置，而不只是最前面，会变化几条边？
- 能否把本题继续优化到 `O(n)`？需要如何按端点值维护最优边界组合？
- 为什么“最多减少两个接缝”不能直接推出最优区间？
