# 相机 UI 业务状态逻辑

- 状态：`[learning] [interview] [project]`
- 来源：2026-06-22 影石相机 UI 开发实习一面；后续二面和 offer 前复盘

## 我的理解

相机 UI 不是互联网前端那种只做网页和按钮样式，而是嵌入式设备上的交互层。它一边接收用户按键、触摸、菜单操作，另一边要和底层相机控制模块交互，比如开始录像、停止录像、切换模式、设置分辨率、读取电量、读取存储卡状态、同步蓝牙或 Wi-Fi 连接状态。

更适合我的类比是：相机 UI 在角色上有点像操作系统里的 shell，都是用户和底层能力之间的交互入口。shell 把用户输入命令转换成系统调用或程序执行；相机 UI 把用户点击、按键和菜单操作转换成对相机控制模块的调用。区别是相机 UI 更偏图形界面、事件驱动、状态机和异步回调，不能简单说“相机 UI 就是 shell”。

## 易错点

- `[wrong]` 不能问成“是不是做界面和按钮，类似互联网前端”。这会暴露对岗位理解浅。
- `[learning]` 更好的表达是“设备端 UI / 嵌入式 HMI / 业务状态逻辑”，但面试里不要硬堆术语，要用具体例子解释。
- `[weak]` 需要把用户事件、设备状态、底层接口、界面刷新这四个关键词讲顺。

## 面试推荐回答

如果被问“你理解相机 UI 开发做什么”，可以回答：

> 我理解相机 UI 不是单纯画界面，而是运行在相机设备上的交互层。它一边接收用户的按键、触摸和菜单操作，另一边要和底层相机控制模块交互，比如开始录像、停止录像、切换拍摄模式、设置分辨率、读取电量和存储状态。这里面比较重要的是状态逻辑，比如当前是否允许录像、底层执行成功后 UI 怎么刷新、失败时怎么提示、异步回调回来后怎么保证界面显示和真实设备状态一致。我之前做过 T-Box 模块间事件通知和 V853 视频采集项目，虽然不是直接做相机 UI，但事件回调、状态同步、设备端功能链路这些经验可以迁移。

如果想使用 shell 类比，可以回答：

> 我理解它在角色上有点像操作系统里的 shell，都是用户和底层能力之间的一层交互入口。shell 把用户输入的命令转换成系统调用或程序执行，相机 UI 则把用户的按键、触摸、菜单操作转换成对相机控制模块的调用。区别是相机 UI 更偏图形界面和事件驱动，还要处理设备状态变化、异步回调和界面刷新一致性。

3. 页面销毁后底层异步回调回来，怎么避免访问野指针？
